# Best Practices 요약

- 원문: https://code.visualstudio.com/docs/agents/best-practices
- 문서 제목: Best practices for using AI in VS Code
- 원문 수정일: 2026-09-16

## 문서 핵심

이 문서는 VS Code에서 AI를 효과적으로 활용하는 방법을 설명한다. 핵심은 “작업에 맞는 도구를 고르고, 컨텍스트를 깔끔하게 제공하며, 결과를 검증하는 것”이다.

## 1. 작업에 맞는 도구 선택

AI 도구는 여러 방식으로 제공된다.

- Inline suggestions: 코드 작성 중 빠른 보완
- Inline chat: 특정 코드 영역을 바로 수정
- Agents: 여러 파일을 수정하는 작업에 적합
- Plan: 구현 전 구조 설계
- Smart actions: 커밋 메시지 생성, 코드 이름 변경 등 단일 작업

즉, 작은 수정은 인라인 도구, 큰 범위 변경은 에이전트, 설계 단계는 Plan을 쓰는 것이 적절하다.

## 2. 작은 작업부터 시작

새 프로젝트에서 에이전트를 사용할 때는 큰 기능 전체를 한 번에 맡기기보다 작은 작업으로 나누어 진행하는 게 좋다.

권장 흐름:

1. 신뢰할 수 있는 프로젝트 열기
2. 관련 변경 사항을 커밋/stash로 정리
3. 작은 작업과 결과를 명확히 정의
4. 필요한 파일, 오류, 제약 조건을 함께 전달
5. 검토와 테스트를 직접 수행
6. 의도에 맞는 변경만 커밋

## 3. 좋은 프롬프트 작성법

질문의 품질이 결과를 좌우한다.

좋은 프롬프트의 요소:

- 입력, 출력, 제약 조건을 구체적으로 명시
- 비슷한 언어/프레임워크/라이브러리를 지정
- 기대 결과나 테스트 케이스 포함
- 애매한 표현을 피하고 명확하게 표현
- 복잡한 작업은 단계별로 쪼개기

예시:

```text
Write a TypeScript function that validates email addresses.
Return true for valid addresses, false otherwise. Don't use regex.
Example: validateEmail("user@example.com") returns true
Example: validateEmail("invalid") returns false
```

## 4. 올바른 컨텍스트 제공

AI는 관련 컨텍스트가 많을수록 더 정확하게 동작한다.

- 특정 파일, 폴더, 심볼을 참조
- 웹 문서나 GitHub 리포지토리 정보를 fetch로 가져오기
- 테스트 결과, 터미널 출력, Git 변경 사항 함께 전달
- 이미지나 스크린샷을 함께 제공
- 브라우저 도구를 사용해 실제 UI 흐름을 검증하게 하기

AI가 코드베이스 전체를 자동으로 탐색하지만, 중복되거나 불필요한 컨텍스트를 줄이는 것이 중요하다.

## 5. 적절한 모델 선택

모델마다 특성이 다르다.

- 빠르고 가벼운 모델: 보일러플레이트, 단순 생성
- 추론 중심 모델: 설계, 디버깅, 복잡한 문제 해결
- 최신 모델: 성능이 높아지는 경우가 많음
- BYOK: 추가 모델 선택권과 호스팅 제어 가능

또한 AI credit 사용량을 줄이기 위해 작업의 난이도에 따라 모델을 나누는 것이 좋다.

## 6. 구현 전에 계획을 먼저 세우기

복잡한 여러 파일 변경은 계획 단계와 구현 단계를 분리하는 것이 좋다.

권장 흐름:

1. 코드 탐색
2. Plan으로 구현 설계 준비
3. 구현 단계에서 테스트와 기대 결과 함께 전달
4. 결과를 검토

이렇게 하면 잘못된 구현을 시도하는 비용을 줄일 수 있다.

## 7. 결과 검증은 필수

AI가 작성한 코드는 항상 검토해야 한다.

- 생성된 코드 읽기
- 엣지 케이스 검토
- 테스트 실행
- 보안 이슈 확인
- 민감 정보 과입력 방지

특히 보안적으로는 injection, 하드코딩된 비밀, 입력 검증 누락 같은 문제를 점검해야 한다.

## 8. 에이전트 하니스 선택

에이전트는 하니스에 따라 동작 방식과 도구가 다르다.

- Copilot: 일반적인 개발 작업에 적합
- Claude / Codex: 공급자별 기능 활용
- Cloud target: 팀 협업 및 원격 실행에 유리

작업 성격에 맞는 하니스를 선택하면 더 나은 결과를 얻을 수 있다.

## 9. 프로젝트 맞춤화

프로젝트별 규칙이 필요하면 커스터마이징을 추가할 수 있다.

- Custom instructions: 프로젝트 규약
- Custom agents: 특정 역할 정의
- Skills: 반복 작업 패턴 저장
- MCP servers: 외부 시스템 연결

권장 사항:

- 지침 파일은 짧고 핵심만 유지
- `applyTo` 패턴으로 범위 제어
- 사용하지 않는 도구는 비활성화
- 노이즈 파일은 검색 제외

## 10. 세션과 컨텍스트 관리

대화가 길어지면 컨텍스트가 쌓여 품질이 떨어질 수 있다.

- 관련 없는 작업은 새 세션으로 분리
- 필요 없는 대화 삭제
- [/compact]로 컨텍스트 정리
- 서브에이전트로 탐색 작업 분리
- 병렬 세션으로 독립적인 태스크 동시 수행

## 11. AI 크레딧 사용 최적화

AI 기능은 사용량과 비용을 고려해야 한다.

- 단순 작업은 저비용 모델 사용
- 복잡한 설계와 디버깅은 고급 모델로 분리
- 불필요한 대화 기록 및 맥락 제거
- 실행 전에 계획을 세워 낭비를 줄임

## 12. 대규모 코드베이스에서의 사용

대형 프로젝트에서는 다음이 중요하다.

- 워크스페이스 인덱싱 활용
- 멀티루트 워크스페이스로 경계 설정
- 프로젝트 지침으로 구조 설명
- 병렬 세션으로 독립 작업 나누기
- 큰 변경은 Plan agent로 먼저 설계

## 핵심 요약

AI를 잘 쓰는 핵심은 “오래 생각하게 만들기보다, 작업을 좁히고, 컨텍스트를 정리하고, 결과를 검증하는 것”이다. VS Code는 이 과정을 지원하는 여러 도구를 제공하므로, 가장 적절한 도구와 모델을 선택하고 작업 단위를 잘 나누는 것이 중요하다.
