# Review and Revert Changes 요약

- 원문: https://code.visualstudio.com/docs/agents/run/review-code-edits
- 문서 제목: Review and revert agent changes
- 원문 수정일: 2026-10-07

## 변경 검토

Agent Host 세션은 파일 편집 도구·터미널·스크립트·MCP를 통해 변경 사항을 세션 폴더나 worktree에 직접 저장한다. 개별 편집을 Keep·Undo하는 pending review 상태가 아니므로 diff, Source Control, PR 흐름으로 검토한다. Local harness는 지원되는 편집을 pending으로 표시해 개별 또는 전체 Keep·Undo를 제공할 수 있다.

Chat view에서는 변경 파일을 응답이나 Source Control에서 열고, Agents window에서는 Changes 패널을 사용한다. `chat.checkpoints.showFileChanges`로 요청별 파일 통계를 표시할 수 있다. 수정 후 테스트·디버거 등으로 검증한다.

## 통합 방법

- 폴더 작업은 Source Control에서 변경을 stage하고 commit한다.
- worktree 작업은 변경을 현재 폴더에 적용하거나 브랜치를 merge·checkout한다.
- Cloud 작업은 pull request 또는 브랜치를 검토한다.

worktree를 통합하기 전 기준·대상 브랜치, 미커밋 파일을 확인하고 변경을 검토한 뒤 테스트한다. 통합 후에도 대상 작업 공간에서 다시 검증한다.

## 요청 수정과 Checkpoint

이전 요청을 편집하면 그 요청과 이후 요청에서 생긴 파일 변경을 되돌린 뒤 수정 요청을 다시 실행한다. Checkpoint 복원은 선택 시점 이후의 파일 변경과 대화 기록을 복구한다. 복원 후 Redo로 취소된 변경을 다시 적용할 수 있고, checkpoint에서 fork해 해당 시점까지의 대화로 별도 작업을 시작할 수 있다.

Checkpoint는 터미널 명령, 배포, 네트워크 요청, 외부 서비스 변경을 되돌리지 않으며 Git의 영구 버전 관리를 대체하지 않는다.

## 민감한 파일과 세션 목록

`chat.tools.edits.autoApprove`의 glob 규칙으로 `.env`나 작업 공간 설정 등 특정 파일 편집 전 승인을 요구할 수 있다. 이는 변경 후 diff를 검토하는 절차와 별개다. 완료 세션의 변경 통계는 세션 목록에서 열어 검토하고 harness에 따라 적용·merge·브랜치 checkout을 선택한다.

## 핵심 요약

에이전트 변경은 저장된 diff를 직접 검토하고 검증한 뒤 통합한다. Checkpoint는 파일과 대화를 복구하지만 외부 효과는 되돌리지 않으므로, 실험 세션을 지우기 전에 Git과 외부 시스템 상태를 확인한다.
