## 도구의 역할

도구는 언어 모델이 개발 환경에서 행동하게 하는 수단이다. 도구가 없으면 모델은 텍스트만 생성하지만, 도구가 있으면 파일을 읽고 쓰고, 코드를 검색하고, 터미널 명령을 실행하며, 외부 서비스와 연결할 수 있다.

에이전트 루프에서 모델은 작업에 맞는 도구를 선택한다. 각 도구의 결과는 다음 판단을 위한 컨텍스트에 추가된다.

## 도구의 종류

### Built-in 도구

VS Code에 기본 제공되는 도구다. 파일 읽기·쓰기, 터미널 실행, 코드베이스 검색, 편집기 탐색 같은 일반적인 개발 작업에 바로 사용할 수 있다.

### MCP 도구

Model Context Protocol 서버가 제공하는 도구다. 로컬 또는 원격으로 실행할 수 있으며 데이터베이스, API, 브라우저, 외부 서비스와 연결할 때 사용한다.

### Extension 도구

VS Code 확장이 Language Model Tools API를 통해 제공하는 도구다. 설치된 확장의 기능을 편집기와 통합해 사용할 수 있다.

## 도구 사용 방식

모델은 사용 가능한 도구 목록을 보고 작업에 필요한 도구를 자율적으로 선택한다. 사용자가 특정 도구 사용을 원하면 프롬프트에서 `#` 뒤에 도구 이름을 직접 참조할 수도 있다.

## 도구를 제한하는 이유

사용 가능한 도구를 작업에 필요한 범위로 좁히면 다음 효과가 있다.

- 불필요한 도구 출력이 줄어 컨텍스트를 보존한다.
- 불필요한 호출과 AI credit 사용을 줄인다.
- 모델이 적절한 도구에 집중해 관련성이 높아진다.
- 선택해야 할 도구 수가 줄어 성능이 좋아진다.

도구 사용 가능 범위는 채팅 요청별로 지정하거나 Custom agent에 고정할 수 있다. Copilot 하니스에서는 사용자 프로필에서 한 번 설정한 도구 구성이 모든 세션에 적용된다.

## 승인과 신뢰

도구는 파일과 환경을 변경하거나 외부 서비스에 접근할 수 있으므로 VS Code는 다음 제어 기능을 제공한다.

- **승인 프롬프트**: 부작용이 있는 도구는 실행 전에 확인을 요청한다. 한 번, 현재 세션, 이후 모든 호출 범위로 승인할 수 있다.
- **URL 승인**: URL에 접근할 때 요청과 응답 콘텐츠를 확인하는 2단계 절차를 사용한다.
- **권한 수준**: 수동 승인부터 광범위한 자동 승인까지 에이전트 자율성의 정도를 정한다.

도구를 자동 승인하더라도 파일 변경과 외부 호출의 결과는 검토해야 한다. 신뢰 경계와 샌드박싱을 함께 사용하면 위험을 줄일 수 있다.

## 핵심 요약

도구는 모델의 텍스트 생성을 실제 개발 작업으로 연결한다. 필요한 도구만 활성화해 컨텍스트와 비용을 관리하고, 파일 변경·터미널·외부 서비스 호출에는 승인과 신뢰 정책을 적용해야 한다.
