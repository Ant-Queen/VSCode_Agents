# Agent Harnesses 개념 요약

- 원문: https://code.visualstudio.com/docs/agents/concepts/agent-harnesses
- 문서 제목: Understand agent harnesses
- 원문 수정일: 2026-09-16

## 핵심 개념

하니스(harness)는 언어 모델을 실제 에이전트로 바꾸는 런타임 계층이다. 모델이 생각하고 도구를 요청하면, 하니스는 그 요청을 관리하고, 승인/권한을 적용하며, 작업 상태를 세션에 기록한다.

즉, 모델이 행동을 제안하면 하니스가 “이를 실제로 실행할 수 있는 시스템”으로 연결한다.

## 1. 하니스가 하는 일

하니스의 주요 역할:

- 요청 수신
- 모델에 필요한 컨텍스트와 도구 정의 전달
- 모델의 도구 호출 처리
- 권한 규칙 및 승인 적용
- 도구의 결과를 다시 모델로 전달
- 세션 상태와 코드 변경 기록 유지

이 흐름을 한 번의 turn으로 간주할 수 있다.

## 2. 하니스와 다른 개념의 차이

하니스는 다음 요소와 구분된다.

- Language model: 추론 수행
- Agent role: 어떤 동작 스타일/지침을 가지는지
- Session target: 어떤 하니스나 클라우드 타깃을 사용할지
- Execution environment: 코드가 어디에서 실행되는지

즉, 모델은 생각을 하고, 하니스는 그 생각이 실제로 실행되게 하는 오케스트라 역할을 맡는다.

## 3. 하니스 선택이 바꾸는 것

하니스 선택은 다음에 영향을 준다.

- 사용 가능한 도구
- 모델 옵션
- 제공되는 워크플로우
- 승인 방식과 권한 규칙

다만 하니스가 곧 코드가 실행되는 위치를 정하는 것은 아니다. 실행 위치는 execution environment에서 결정된다.

## 4. 세션 타깃과 환경

VS Code는 여러 실행 환경을 지원한다.

- 로컬 머신
- 연결된 호스트
- Dev Container
- 클라우드 인프라

예를 들어, Copilot, Claude, Codex 같은 하니스는 같은 환경 안에서 다르게 동작할 수 있으며, 컨테이너 선택은 하니스 자체가 아니라 실행 환경을 바꾸는 것이다.

## 5. 코드 격리와 worktree

작업 환경은 코드 격리 방식에 따라 달라질 수 있다.

- Folder isolation: 현재 워크스페이스에 직접 수정
- Worktree isolation: 별도의 Git worktree를 사용
- Dev Container: 컨테이너 내부의 워크스페이스 사용

중요: worktree는 보안 경계가 아니다. 파일 접근 제한이나 네트워크 차단을 제공하지 않는다. 이건 별도의 sandboxing 기능이 담당한다.

## 6. 요약

하니스는 AI 에이전트의 실제 실행 엔진이다. 모델이 아이디어를 생성하면 하니스는 도구와 승인, 환경, 세션 상태를 조정해 그 아이디어를 작업으로 바꾼다. 결과적으로 하니스 선택은 모델 자체보다 더 넓은 실행 컨텍스트를 결정한다.
