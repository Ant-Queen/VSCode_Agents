# Memory 요약

- 원문: https://code.visualstudio.com/docs/agents/run/memory
- 문서 제목: Use memory with agents in VS Code
- 원문 수정일: 2026-10-07

## Memory의 목적과 범위

Memory tool은 사용자 선호, 저장소 지식, 현재 작업의 임시 컨텍스트를 로컬 파일에 저장해 이후 대화에서 참고하게 한다. 범위는 세 가지다.

| 범위 | 경로 | 용도 |
| --- | --- | --- |
| User | `/memories/` | 모든 작업 공간에 적용되는 개인 선호와 반복 패턴 |
| Repository | `/memories/repo/` | 현재 작업 공간의 구조, 명령, 규칙 |
| Session | `/memories/session/` | 현재 대화의 임시 정보와 계획 |

User memory의 앞 200줄은 대화 시작 시 자동으로 로드된다. Repository memory는 로컬에 저장되며 팀 공유 문서가 아니다. Session memory는 대화가 끝나면 유지되지 않는다.

## 사용과 관리

자연어로 기억할 내용을 요청하면 에이전트가 적절한 범위에 저장하거나 기존 메모리를 갱신한다. 새 대화에서 관련 내용을 물으면 저장된 정보를 찾아 답한다. Command Palette의 Chat: Show Memory Files에서 파일을 확인할 수 있고, Chat: Clear All Memory Files는 모든 범위의 memory를 삭제한다.

팀이 의존하는 아키텍처 결정, 개발 명령, 공통 규칙은 로컬 memory에만 두지 않는다. 코드와 설정을 확인한 뒤 검토 가능한 프로젝트 문서나 custom instructions로 옮긴다.

## Copilot Memory와 구분

Copilot Memory는 GitHub가 호스팅하는 별도 기능으로 저장소 지식을 Copilot CLI, cloud agent, code review 등 여러 표면에서 공유한다. VS Code의 로컬 Memory tool과 달리 Repository 범위 중심이며, 사용자·세션 개인 메모리는 공유하지 않는다. 사용하려면 VS Code와 GitHub 저장소에서 각각 활성화해야 한다.

Copilot Memory는 저장소 범위의 통찰을 검증해 활용하고 오래된 정보는 28일 후 만료된다. 활성화되지 않았거나 조건을 충족하지 못하면 Repository memory는 로컬로 남는다.

## 핵심 요약

반복되는 개인 선호와 작업 공간 지식을 적절한 범위의 memory로 보존할 수 있다. 팀의 기준 정보는 검토 가능한 저장소 문서로 관리하고, GitHub 제품 간 공유가 필요할 때만 Copilot Memory를 사용한다.
