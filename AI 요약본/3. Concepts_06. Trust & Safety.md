# Trust & Safety 요약

- 원문: https://code.visualstudio.com/docs/agents/concepts/trust-and-safety
- 문서 제목: Understand trust and safety for AI agents
- 원문 수정일: 2026-10-07

## 핵심 원칙

에이전트는 파일 수정, 터미널 실행, 외부 서비스 호출 등 다양한 작업을 수행할 수 있다. 따라서 VS Code는 사용자가 작업을 제어할 수 있도록 여러 보안 장치를 둔다.

중요한 원칙은 "에이전트는 능력이 많아도 최종 결정권은 사용자에게 있다"는 것이다.

## 사용자가 제어할 수 있는 요소

- 변경 사항 리뷰
- 승인 설정
- 민감 파일 보호
- 툴 권한 수준 지정
- 작업 중단 및 체크포인트 복원

## 트러스트 경계

VS Code는 작업 영역, 확장 프로그램, MCP 서버, 네트워크 도메인마다 신뢰 경계를 둔다. 이 경계를 넘어서야 특정 기능이 활성화된다.

예를 들면:

- 워크스페이스 신뢰 여부
- 확장 프로그램 게시자 신뢰
- MCP 서버 신뢰
- 외부 URL 접근 신뢰

## 에이전트 샌드박싱

샌드박싱은 터미널 명령과 자식 프로세스가 허용된 파일 시스템과 네트워크 범위를 벗어나지 못하게 보호한다.

목적:

- 승인 fatigue 완화
- 위험한 명령 실행 방지
- 프롬프트 인젝션 영향 축소
- 외부 서비스 오작동 방지

샌드박싱은 OS 수준에서 강제되므로, 단순한 승인 확인보다 더 강력한 경계가 된다.

## AI의 한계

LLM은 실수할 수 있다.

- 틀린 코드 생성
- 경계 케이스 누락
- 보안상 취약한 구현
- 오래된 지식 기반의 부정확한 답변

그래서 AI 생성 결과는 "초안"으로 보고 검토가 반드시 필요하다.

## 핵심 요약

VS Code의 보안 모델은 "에이전트가 수행할 수 있는 행동"과 "사용자가 승인할 수 있는 행동"을 분리해 설계한다. 워크스페이스 신뢰, 권한 수준, 샌드박싱, 리뷰 체계를 함께 사용해 에이전트의 자율성을 안전 범위 안에서 운영한다.
