# Trust & Safety 개념 요약

- 원문: https://code.visualstudio.com/docs/agents/concepts/trust-and-safety
- 문서 제목: Understand trust and safety for AI agents
- 원문 수정일: 2026-09-16

## 핵심 개념

AI 에이전트는 파일을 읽고 수정하고, 터미널을 실행하고, 외부 네트워크에 접근할 수 있다. 따라서 에이전트가 실제로 어떤 행동을 할지 제어하는 보안 체계는 매우 중요하다.

VS Code는 신뢰(Trust)와 승인(Approval), 격리(Sandboxing) 체계를 통해 사용자가 최종 책임을 유지하도록 설계한다.

## 1. 사용자는 여전히 통제권을 가진다

에이전트는 작업을 수행할 수 있지만, 다음 사항은 반드시 사용자가 확인한다.

- 변경 사항 리뷰
- 민감한 작업의 승인
- 권한 수준 조정
- 결과를 테스트하고 검증
- 커밋 전 최종 확인

특히 “정지”는 이미 실행된 작업을 되돌리지 못할 수 있다. 따라서 변경 전 검토는 필수다.

## 2. 신뢰 경계(Trust boundaries)

VS Code는 보안 모델을 경계 단위로 나눈다.

- Workspace: 작업 영역이 신뢰되었는지
- Extension publisher: 확장 프로그램 출처 신뢰 여부
- MCP server: 서버 접근 허용 여부
- Network domain: 외부 URL 접근 허용 여부

이 경계는 각각 별도로 신뢰를 부여하거나 취소할 수 있다. 예를 들어 작업 영역이 신뢰되지 않은 상태에서는 에이전트 기능이 제한될 수 있다.

## 3. 승인과 권한 수준

도구가 실행되는 방식은 권한 수준에 따라 달라진다.

- 수동 승인: 실행 전 확인
- 부분 자동 승인: 정해진 동작만 자동 실행
- 높은 자율성 모드: 비교적 많은 동작을 자동 수행

특히 민감한 파일 수정이나 외부 네트워크 작업은 명시적인 승인 체계가 필요하다.

## 4. Agent sandboxing

sandboxing은 OS 수준에서 제한을 적용해 에이전트가 지나치게 큰 권한을 가지지 못하게 한다.

- 파일 시스템 제한: 중요한 경로 접근 차단
- 네트워크 제한: 허용된 도메인만 접속 가능

이를 통해 자동 승인된 터미널 명령조차 대표적으로 위험한 영역에 접근하지 못하도록 한다.

주의:

- sandboxing은 터미널 명령에 적용되며, 파일 도구 자체는 별도 권한 체계를 따른다.
- Dev Container는 격리 환경이지만 보안 경계가 자동으로 완전해지는 것은 아니다.

## 5. AI의 한계와 위험

모델은 다음 문제를 일으킬 수 있다.

- 잘못된 코드 생성
- 엣지 케이스 누락
- 보안 취약점 도입
- prompt injection에 노출

즉, AI 결과는 “초안”으로 보고 검증해야 한다. 보안, 데이터 무결성, 중요한 로직은 반드시 사람이 확인해야 한다.

## 6. 요약

에이전트는 강력한 도구를 제공하지만, 그만큼 검증과 제한이 중요하다. VS Code는 승인, 신뢰 경계, 샌드박싱, 체크포인트를 조합해 사용자가 작업을 제어할 수 있게 설계한다. 개발자는 AI의 결과를 신뢰하기보다 검토하고 책임지는 자세가 필요하다.
