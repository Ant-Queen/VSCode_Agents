## 언어 모델의 역할

VS Code의 AI 기능은 대규모 언어 모델(LLM)을 사용한다. 모델은 프롬프트를 처리해 텍스트를 생성하고, 그 결과는 설명, 코드 편집 또는 도구 호출 요청이 될 수 있다.

프롬프트에는 사용자의 메시지, 대화 기록, 파일 내용, 도구 출력, 사용자 정의 지침이 포함된다. 모델이 파일을 직접 읽거나 코드를 실행하는 것은 아니며, 에이전트 루프가 모델의 도구 호출 요청을 해석하고 실행한다.

모델에는 다음 특성이 있다.

- 같은 프롬프트에도 결과가 달라질 수 있는 **비결정성**
- 제공된 컨텍스트의 관련성과 품질에 영향을 받는 **컨텍스트 의존성**
- 학습 시점 이후의 정보나 최신 API를 틀릴 수 있는 **지식 경계**

## 모델 사용 방식

- GitHub Copilot 플랜에 포함된 Anthropic, Google, OpenAI 등 여러 공급자의 모델을 선택할 수 있다.
- **BYOK(Bring Your Own Key)**로 자체 API 키를 사용해 다른 공급자의 모델이나 로컬·오프라인 모델을 연결할 수 있다.
- BYOK는 GitHub Copilot 플랜 없이도 VS Code의 채팅과 에이전트 기능을 사용할 수 있게 한다.

## 컨텍스트 윈도우

컨텍스트 윈도우는 한 요청에서 모델이 처리할 수 있는 전체 정보량이다. 시스템 프롬프트, 사용자 정의 지침, 대화 기록, 파일, 도구 출력이 모두 포함된다.

한도에 도달하면 VS Code가 오래된 대화를 자동 요약한다. 사용자는 `/compact` 명령으로 직접 압축할 수 있으며, `/compact focus on the API design decisions`처럼 요약 초점을 지정할 수도 있다. 압축 과정에서 초기 대화의 세부사항이 사라질 수 있으므로 중요한 규칙은 사용자 정의 지침에 두는 것이 좋다.

## Thinking과 reasoning

추론 모델은 최종 답변 전에 내부적으로 여러 접근법과 트레이드오프를 검토한다. 복잡한 디버깅, 아키텍처 설계, 대규모 리팩터링에는 유리하지만 단순한 보일러플레이트에는 지연만 늘릴 수 있다.

**Thinking effort**가 높을수록 일반적으로 품질이 향상되지만 지연과 토큰 사용도 증가한다. thinking token은 화면에 보이지 않더라도 컨텍스트 윈도우와 비용에 포함된다.

## 모델 선택과 비용

- 빠른 모델: 간단한 질문, 보일러플레이트, 작은 편집
- 추론 모델: 복잡한 리팩터링, 설계 결정, 다단계 디버깅
- 큰 컨텍스트 모델: 대규모 코드베이스와 긴 대화

자동 모델 선택은 실시간 모델 상태와 작업 복잡도를 고려해 적합한 모델로 요청을 라우팅한다. AI credit 사용량은 모델, 토큰 수, thinking effort, 컨텍스트 크기, 도구 사용량의 영향을 받으며 프롬프트 캐싱은 반복 토큰 비용을 낮출 수 있다.

## BYOK의 고려 사항

BYOK는 모델 선택 폭, 실험, 로컬 컴퓨팅, 오프라인 환경을 제공한다. 반면 인라인 제안과 임베딩 기반 semantic search에는 여전히 GitHub Copilot 플랜이 필요할 수 있고, 도구 호출·비전·추론 지원 여부는 모델마다 다르다. BYOK 모델 출력에는 책임 있는 AI 필터링이 보장되지 않을 수 있으므로 결과를 주의 깊게 검토해야 한다.

## 핵심 요약

언어 모델은 에이전트의 추론 엔진이지만 직접 파일이나 실행 환경에 접근하지는 않는다. 작업 복잡도와 컨텍스트 규모에 맞는 모델을 선택하고, 비용·지연·BYOK의 보안 및 기능 차이를 함께 고려해야 한다.
