# Session History 요약

- 원문: https://code.visualstudio.com/docs/agents/run/sessions/session-history
- 문서 제목: Sync and query session history
- 원문 수정일: 2026-10-07

## 기록 동기화와 개인정보

VS Code는 Copilot 세션 기록을 검색 가능한 형태로 관리하고, 기본 설정에 따라 GitHub 계정으로 동기화한다. 동기화 세션은 기본적으로 개인 기록이며 명시적으로 공유해야 다른 저장소 협업자가 볼 수 있다. 동기화를 끄려면 `chat.sessionSync.enabled`를 `false`로 설정한다. 저장소별 제외는 `chat.sessionSync.excludeRepositories`에 `owner/repo` 또는 glob 패턴으로 지정한다.

토큰, API 키, 자격 증명 같은 비밀 값은 동기화 전에 필터링된다. 동기화된 기록은 GitHub.com에 남아 있을 수 있으므로 완전히 지우려면 Command Palette의 Delete Session Sync Data 명령에서 로컬·클라우드 또는 클라우드만 삭제를 선택한다. 삭제는 되돌릴 수 없다.

Copilot Business·Enterprise에서는 GitHub 정책과 VS Code `CopilotSessionSync` 정책이 동기화를 통제할 수 있다. 정책으로 비활성화되면 사용자가 설정을 재정의할 수 없다. 관리자는 기본적으로 개인 세션 기록에 접근하지 않는다.

## Chronicle로 검색

Chronicle은 로컬 세션 인덱스를 검색해 과거 작업 요약과 비용 팁을 제공한다.

- `/chronicle:standup`: 최근 세션을 저장소·브랜치별로 요약한다.
- `/chronicle:tips`: 사용 패턴에서 Copilot 활용 팁을 제안한다.
- `/chronicle:cost-tips`: 사용량과 비용을 줄일 방법을 찾는다.
- `/chronicle:search <query>`: 문구, 파일 경로, PR·이슈 참조로 검색한다.
- `/chronicle:reindex`: 로컬 인덱스를 다시 만들고 설정에 따라 동기화한다.

자연어로 과거 수정 파일이나 특정 주제 작업을 물어볼 수도 있다. 로컬 인덱스는 저장소·브랜치·시간, 대화 내용, 파일 경로와 PR·이슈·커밋 참조 등을 추적한다.

## 동기화 관리

상태 표시에서 꺼짐, 동기화 중, 완료된 세션 수, 정책에 의한 차단, 오류를 확인할 수 있다. 기록을 기기 안에만 두려면 동기화를 끄며, 복원·충돌 등으로 세션이 누락됐을 때 reindex를 실행한다.

## 핵심 요약

Session History는 과거 Copilot 작업을 검색·요약하고 기기 간 이어 볼 수 있게 한다. 민감한 저장소는 동기화 제외를 설정하고, 기록 삭제는 로컬 인덱스와 클라우드 복사본의 범위를 확인한 뒤 실행한다.
