# Agent Sandboxing 요약

- 원문: https://code.visualstudio.com/docs/agents/run/agent-sandboxing
- 문서 제목: Sandbox Copilot Agent Host sessions
- 원문 수정일: 2026-10-07

## 샌드박스 경계

Agent Host 샌드박싱은 터미널 명령과 자식 프로세스의 파일·네트워크 접근을 제한한다. 설정에 따라 Agent Host가 실행·관리하는 MCP 및 language server에도 적용된다. 승인 설정과 별도이며, 승인된 명령도 샌드박스 제한을 받는다.

샌드박스는 가상 머신이나 사용자 계정 경계가 아니며 엔드포인트 보안을 대체하지 않는다. 네트워크 접근, 인증 정보, 추가 경로, 개발 도구 접근, 샌드박스 밖 실행은 격리를 약화시킨다.

## 지원 플랫폼과 활성화

Agent Host 기본 Copilot SDK 도구 구현에 적용된다. macOS는 별도 전제 조건이 없고, Linux·WSL2는 `bubblewrap`과 `socat`이 필요하다. WSL1은 지원하지 않는다. Windows는 2026년 9월 보안 업데이트가 필요하고 지원 상태는 Experimental이다.

실행 호스트에서 `chat.agent.sandbox.enabled`를 `on`으로 설정한 뒤 새 Agent Host 세션을 시작한다. 원격 Agent Host라면 클라이언트가 아니라 원격 호스트에서 설정과 의존성을 준비한다. 현재 세션만 Permissions에서 샌드박싱을 바꿀 수도 있다. `/sandbox policy`는 현재 적용된 정책을 Markdown으로 보여준다.

## 접근 범위 설정

기본 작업 폴더는 읽기·쓰기가 허용된다. `chat.agent.sandbox.fileSystem.userConfiguredPaths`에서 추가 `readwritePaths`, `readonlyPaths`, `deniedPaths`를 지정한다. 충돌 시 denied, readonly, readwrite 순으로 제한이 우선한다. `allowDevToolAccess`는 개발 도구 경로와 설정·캐시에 대한 추가 접근을 제어한다.

네트워크는 별도 설정이다. `chat.agent.sandbox.network.allowNetwork`는 기본 `true`이므로 활성화만으로 외부 접속이 차단되지 않는다. 필요하면 끄거나 `allowedDomains`, `deniedDomains`로 제한한다. 로컬 네트워크 접근은 별도 허용이 필요하다.

MCP·language server와 Git·GitHub 인증 전달도 각각 설정할 수 있다. 인증을 전달하면 해당 프로세스가 계정 권한으로 작업할 수 있다.

## 샌드박스 밖 실행

명령이 정책에 막히면 필요한 경로·도메인만 허용하는 것이 우선이다. 기본 설정에서는 에이전트가 샌드박스 밖 실행 승인을 요청할 수 있다. 허용하면 해당 명령 또는 세션의 파일·네트워크 제한이 사라질 수 있다. `chat.agent.sandbox.allowUnsandboxedCommands`로 이 우회 요청을 막을 수 있다.

## 핵심 요약

샌드박스는 에이전트 명령의 영향 범위를 줄이는 계층이며 기본적으로 네트워크가 열려 있다. 실행 호스트에서 정책을 확인하고 필요한 경로·도메인만 허용하며, 샌드박스 밖 실행 승인도 신중하게 다룬다.
