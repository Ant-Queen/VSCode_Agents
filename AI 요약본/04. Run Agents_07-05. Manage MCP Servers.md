# Manage and Troubleshoot MCP Servers 요약

- 원문: https://code.visualstudio.com/docs/agents/run/manage-mcp-servers
- 문서 제목: Manage and troubleshoot MCP servers

## 서버 관리 화면 열기

Chat view에서 관리할 서버의 에이전트 하니스를 선택한 다음, 제목 표시줄의 **Open Customizations** 또는 명령 팔레트의 **Chat: Open Customizations**를 실행하고 **MCP Servers**를 연다. 이 화면은 선택한 하니스에 한정된다.

서버 항목을 선택해 설정을 편집하거나 토글로 활성 상태를 바꾸고, 더 보기 메뉴에서 시작·중지·재시작·제거 작업을 수행할 수 있다. 명령 팔레트의 **MCP: List Servers**로도 서버를 선택하고 사용 가능한 작업을 실행할 수 있다.

## 구성 편집

기존 서버의 유형과 필드를 수정할 수 있다.

- **stdio**: command, arguments, environment variables
- **HTTP**: URL, headers

변경 후 **Save**를 선택한다. 대상 구성 파일에서 지원하지 않는 값이 있으면 저장할 수 없으며, 폼이 수정할 항목을 안내한다. **Discard Changes**는 저장된 설정으로 되돌린다. 폼에 표시되지 않는 기존 속성은 저장 시 유지된다. **Other Properties**로 원본 JSON 항목을 열 수 있다.

이식 가능한 구성은 폼으로 편집할 수 있지만 VS Code 전용 형식은 JSON 읽기 전용으로 표시되므로 원본 파일에서 편집해야 한다. 하니스마다 지원하는 서버 형식과 속성이 다르므로 구성 형식 문서를 확인한다.

## 시작·중지·활성화·제거

- **Start Server**: 설정된 서버를 시작한다.
- **Stop Server**: 현재 실행을 끝내며 이후 요청에서 다시 시작할 수 있다.
- **Restart Server**: 설정을 바꾸거나 문제를 해결한 후 재시작한다.
- **Enable / Disable**: 구성은 유지한 채 사용 가능 여부를 제어한다.
- **Uninstall**: 더 이상 필요하지 않은 서버를 제거한다.

시작 시 신뢰 또는 인증이 필요할 수 있다. 시작에 실패하면 재시도 전에 서버 출력 로그를 확인한다. 중지는 현재 실행만 끝내지만 비활성화하면 서버가 시작되지 않고 도구·리소스·프롬프트·MCP 앱도 사용할 수 없다. 활성 상태는 공유 구성과 별도이므로 서버 비활성화가 팀원의 설정을 바꾸지는 않는다.

수동 구성 서버에 제거 작업이 제공되지 않으면 원본 파일 전체가 아니라 해당 서버 항목만 제거한다. 자동 검색으로 다시 나타나는 서버는 검색 원인을 확인한다. 설치된 서버는 Extensions view의 MCP 설치 항목에서 제거할 수도 있다.

## 자동 시작 설정

메시지를 보낼 때 도구를 찾기 위해 서버를 시작하는 동작은 `chat.mcp.autostart`로 제어한다.

- `never`: 이 자동 시작 단계에서 서버를 시작하지 않는다.
- `onlyNew`: 한 번도 실행된 적 없는 서버를 시작한다.
- `newAndOutdated`(기본값): 새 서버 또는 구성이 변경된 서버를 시작한다.

비활성화되었거나 오류 상태인 서버는 자동 시작에서 제외된다. `never`는 Copilot 하니스 자체의 시작 동작까지 막는 설정이 아니므로, 특정 서버가 시작되지 않도록 하려면 해당 서버를 비활성화한다.

## 구성 공유와 원격 환경

호환되는 Copilot 구성은 작업 공간 루트의 `.mcp.json`에 저장해 팀과 공유할 수 있다. 구성 공유가 서버 런타임 설치나 자격 증명 전달까지 해주지는 않는다. 비밀 값을 커밋하지 말고 구성 형식에 맞는 인증·비밀 관리 방식을 사용한다.

stdio 서버는 명령이 실행되는 환경에 런타임과 의존성이 설치되어 있어야 한다. 원격 작업 공간에서는 원격 환경에 서버를 구성하거나 원격 사용자 설정을 사용한다. HTTP 서버의 URL은 서비스 위치를 지정하며, 설정을 원격에 저장해도 서비스 자체가 이동하는 것은 아니다. Dev Container에서 서버를 제공하려면 `devcontainer.json`의 `customizations.vscode.mcp`를 사용할 수 있다.

## 핵심 요약

Agent Customizations editor에서 MCP 서버 설정과 실행 상태를 관리하고, 실패 시 출력 로그를 먼저 확인한다. 비활성화와 중지는 다르며, 구성 공유 시 비밀 정보를 제외하고 서버 런타임·인증·원격 실행 환경을 별도로 준비한다.
