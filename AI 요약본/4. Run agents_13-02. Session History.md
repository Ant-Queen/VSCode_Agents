# Session History 요약

- 원문: https://code.visualstudio.com/docs/agents/run/sessions/session-history
- 문서 제목: Sync and query session history
- 원문 수정일: 2026-08-19

## 세션 기록과 동기화

VS Code는 Copilot 세션의 검색 가능한 기록을 관리한다. 기본적으로 로컬 에이전트 세션을 GitHub 계정과 동기화해 여러 장치에서 접근하고, VS Code·Copilot CLI·Cloud agent·code review·GitHub Copilot Desktop에서 과거 작업을 조회할 수 있다.

동기화된 세션은 기본적으로 사용자 본인에게만 비공개이며, 명시적으로 공유한 경우에만 다른 사람이 볼 수 있다.

## 동기화 제어

- `chat.sessionSync.enabled`를 `false`로 설정하면 세션을 로컬에만 보관한다.
- `chat.sessionSync.excludeRepositories`에 저장소 이름이나 glob 패턴을 지정하면 해당 저장소만 동기화에서 제외한다.
- Copilot Business·Enterprise에서는 GitHub 정책과 VS Code `CopilotSessionSync` 정책이 동기화를 제어한다.

정책으로 비활성화된 경우 사용자가 설정을 덮어쓸 수 없다. 정책이 활성화되어도 관리자가 개인 세션 기록에 접근할 수 있는 것은 아니다.

## 세션 공유와 개인정보

GitHub.com Agents 탭에서 저장소 접근 권한이 있는 사람에게 특정 동기화 세션을 view-only로 공유할 수 있다. 수신자는 프롬프트, 응답, 파일 변경을 볼 수 있지만 세션을 조정하거나 수정할 수 없다.

토큰, API key, 자격 증명 같은 비밀은 컴퓨터 밖으로 전송되기 전에 자동 제거된다. 기존에 동기화된 데이터를 삭제하려면 명령 팔레트에서 `Delete Session Sync Data`를 실행하고 로컬·클라우드 모두 삭제하거나 클라우드만 삭제하는 범위를 선택한다. 삭제는 되돌릴 수 없다.

## 동기화 상태

Chat view의 Copilot 상태 표시줄에서 다음 상태를 확인한다.

- Not enabled: 로컬에만 저장
- Enabled: GitHub 계정으로 동기화
- N sessions synced: 업로드된 세션 수
- Syncing N sessions: 업로드 진행 중
- Disabled by policy: 조직 정책으로 차단
- Sync error: 마지막 동기화 실패

## Chronicle로 기록 조회

Chronicle 명령으로 과거 작업을 검색하고 요약한다.

| 명령 | 기능 |
| --- | --- |
| `/chronicle:standup` | 최근 24시간 작업을 저장소·브랜치별 standup으로 요약 |
| `/chronicle:tips` | 최근 기록을 분석해 Copilot 활용 팁 제안 |
| `/chronicle:cost-tips` | 토큰·Copilot 비용 절감 기회 제안 |
| `/chronicle:search <query>` | 키워드, 파일, PR·이슈 참조로 검색 |
| `/chronicle:reindex` | 로컬 인덱스를 재생성하고 계정과 동기화 |

자연어로 "어제 어떤 파일을 수정했나?"처럼 질문할 수도 있다. 로컬 기록에는 저장소·브랜치·시간, 대화 내용, 변경 파일, PR·이슈·commit SHA가 저장되며 SQLite 데이터베이스에 보관된다.

## 재인덱싱

백업 복구, 충돌, 세션 디렉터리 수동 삭제, 동기화 재활성화 후 기록이 누락되면 `/chronicle:reindex` 또는 `Reindex Sessions` 명령을 실행한다.

## 핵심 요약

Session History는 세션을 여러 장치와 Copilot 표면에서 다시 찾고, Chronicle로 과거 작업을 검색·요약하게 한다. 민감 저장소는 동기화 제외 설정을 사용하고, 공유·삭제 범위를 신중하게 선택해야 한다.
