# Manage Agent Sessions 요약

- 문서 제목: Manage agent sessions in VS Code
- 원문 수정일: 2026-08-19

## 세션 시작

세션은 프롬프트·응답·컨텍스트·관련 파일을 포함하는 에이전트 작업 단위다. 새 주제마다 새 세션을 시작하면 관련성이 높아지고, 여러 세션을 병렬 실행해 작업별 컨텍스트를 분리할 수 있다.

Agents window에서는 New로 작업 공간·저장소·하니스를 선택한다. Chat view에서는 New Chat으로 현재 작업 공간에 연결된 세션을 만든다. 두 표면은 같은 세션을 공유한다. Agent, 권한 수준, 모델을 추가로 설정할 수 있다.

## 컨텍스트 관리

채팅 입력의 context window control에서 사용량, 토큰 분류, 세션의 AI credit을 확인한다. 대화가 길어지면 자동 compaction이 실행되며 `/compact` 또는 Compact Conversation으로 수동 실행할 수 있다. `/compact focus on the database schema decisions`처럼 보존할 주제를 지정할 수 있다.

컨텍스트 안정성은 prompt caching 재사용과 비용·지연에도 영향을 준다. 전체 초기화를 원하면 새 세션을 만든다.

## 세션의 여러 채팅

Agent Host 세션은 여러 독립 채팅을 포함할 수 있다. 각 채팅은 별도 기록, 제목, 상태, 에이전트·모델을 가지지만 같은 작업 공간과 worktree를 공유한다. 탭을 나란히 배치하거나 그룹을 나눌 수 있다.

새 채팅은 다른 채팅의 기록을 상속하지 않는다. 기존 컨텍스트가 필요하면 세션 fork를 사용한다. 모든 채팅의 변경은 같은 폴더나 worktree에 합쳐지므로 서로 같은 파일을 수정하는 작업은 별도 worktree 세션으로 분리한다.

## 세션 목록과 외부 세션

세션 목록에서는 상태·유형·파일 변경 통계를 확인하고 고정, 보관, 삭제, 그룹화, 순서 변경을 수행한다. Agents window는 모든 작업 공간을, Chat view는 현재 작업 공간을 중심으로 표시한다.

Copilot CLI, GitHub Copilot 앱, Claude Code, Codex에서 생성한 외부 세션도 발견할 수 있다. External 필터에서 None, Recent, Last 24 Hours, Last 7 Days, All 범위를 선택한다. VS Code에서 외부 세션에 메시지를 보내면 Agent Host가 채택하며 더 이상 외부 세션으로 취급되지 않는다.

## 보관과 삭제

Archive 또는 Mark as Done은 세션을 목록에서 숨기지만 복원할 수 있다. Worktree 세션은 보관 시 미커밋 변경을 세션 브랜치에 커밋하려고 하며, 브랜치와 커밋은 유지된다.

Delete는 영구적이고 되돌릴 수 없다. Copilot 세션의 관련 worktree도 삭제될 수 있으므로 통합·커밋 전에 삭제하지 않는다.

## Fork와 사이드 질문

`/fork`는 전체 대화 기록을 가진 독립 세션을 만든다. Checkpoint에서 fork하면 해당 시점까지의 기록만 복사한다. Worktree 세션의 fork는 같은 worktree를 계속 사용할 수 있다.

Agents window의 Copilot·Claude 세션에서는 `/btw <질문>`으로 현재 대화의 최신 컨텍스트를 비공개로 상속하는 side chat을 만들 수 있다. Side chat은 설명 중심이며, 필요하면 작업도 요청할 수 있다.

## 세션 오케스트레이션과 내보내기

Agent Host 에이전트는 세션 목록과 메타데이터를 읽고, 새 세션·채팅을 만들며, 다른 세션에 메시지를 보낼 수 있다. 다른 세션으로 메시지를 보내려면 사용자 확인이 필요하다.

Chat: Export Chat...으로 전체 대화와 프롬프트·응답을 JSON으로 저장할 수 있다. 채팅 메시지는 개별, 전체, 최종 응답만 Markdown으로 복사할 수 있다.

## 핵심 요약

세션은 주제별 컨텍스트와 실행 상태를 관리하는 단위다. 긴 대화는 compact하고, 관련 작업은 여러 채팅이나 병렬 세션으로 나누며, 실험은 fork하고, 완료된 작업은 보관한다. worktree 변경을 보존하기 전에는 세션을 삭제하지 않아야 한다.
