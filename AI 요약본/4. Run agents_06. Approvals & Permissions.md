# Approvals & Permissions 요약

- 원문: https://code.visualstudio.com/docs/agents/run/approvals
- 문서 제목: Manage approvals and permissions
- 원문 수정일: 2026-08-19

## 승인 제어 구조

에이전트는 파일 변경, 터미널 명령, 외부 리소스 접근을 수행할 수 있으므로 VS Code는 전체 자율성을 정하는 권한 수준과 개별 동작을 제어하는 세부 승인 기능을 분리한다.

| 제어 | 대상 | 주요 설정 |
| --- | --- | --- |
| Permission levels | 세션 전체 자율성 | `chat.permissions.default` |
| Tool approval | 개별 도구 실행 | `chat.tools.eligibleForAutoApproval` |
| URL approval | URL·도메인 접근 | `chat.tools.urls.autoApprove` |
| Terminal approval | 터미널 명령 자동 실행 | `chat.tools.terminal.autoApprove` |
| Sandboxing | 명령의 파일·네트워크 접근 | `chat.agent.sandbox.enabled` |

## 권한 수준

Chat input의 permissions dropdown에서 현재 세션의 권한 수준을 선택하고 세션 중 변경할 수 있다.

- **Default Approvals**: 설정된 승인 규칙을 따르고 필요한 경우 확인 대화 상자를 표시한다.
- **Assisted permissions**: 별도 LLM judge가 도구 호출 위험을 평가해 승인된 호출은 자동 실행하고 나머지는 사용자에게 묻는다. Agent Host에서만 사용할 수 있다.
- **Bypass Approvals**: 모든 도구 호출을 확인 없이 승인한다.

Autopilot은 권한 수준이 아니라 에이전트 모드다. 모든 도구를 자동 승인하고, 오류를 재시도하며, 질문에 자동 응답하면서 작업 완료까지 반복한다. Advanced autopilot Preview는 별도 모델이 완료 여부를 평가한다.

Bypass Approvals와 Autopilot은 파괴적인 작업도 승인 없이 실행할 수 있으므로 보안 영향을 이해한 경우에만 사용한다. 조직 관리 규칙은 세션 권한보다 우선해 특정 작업에 승인이나 차단을 요구할 수 있다.

## 도구 승인

도구가 승인을 요청하면 이름과 입력 매개변수를 확인하고 한 번, 현재 세션, 현재 작업 공간, 이후 모든 호출 중 승인 범위를 선택한다.

명령 팔레트의 `Chat: Manage Tool Approval`에서 MCP 서버나 확장별 도구의 사전 승인과 결과 사후 승인을 따로 관리할 수 있다. 외부 데이터를 반환하는 도구는 prompt injection을 포함할 수 있으므로 결과 검토 생략도 신중해야 한다. `chat.tools.eligibleForAutoApproval`에서 민감한 도구를 항상 수동 승인으로 지정할 수 있으며, `Chat: Reset Tool Confirmations`로 저장된 승인을 초기화한다.

## URL 승인

URL 접근은 두 단계로 확인한다.

1. 요청 사전 승인: 해당 도메인으로 요청을 보내는 것을 허용한다.
2. 응답 사후 승인: 가져온 콘텐츠를 채팅과 모델에 전달하기 전에 검토한다.

Trusted Domains에 등록된 도메인은 요청 승인이 자동으로 처리될 수 있지만 응답 검토는 기본적으로 별도다. `chat.tools.urls.autoApprove`에서 URL·glob·도메인별 요청과 응답 승인을 각각 설정할 수 있다.

## 터미널 명령 자동 승인

터미널 도구 자체가 아니라 명령 단위로 승인한다. 기본적으로 안전한 명령은 자동 승인하고 `rm`, `del` 같은 위험 명령은 수동 승인을 요구한다. `chat.tools.terminal.autoApprove`에서 문자열, 정규식, 허용·차단 규칙을 설정할 수 있다.

복합 명령은 모든 하위 명령이 허용 규칙에 맞고 차단 규칙에 걸리지 않아야 자동 승인된다. 셸 별칭, 따옴표 결합, 복잡한 구문과 최소한의 파일 쓰기 탐지는 우회될 수 있으므로 고위험 환경에서는 샌드박싱이나 컨테이너를 사용한다.

## 샌드박스

샌드박스 명령은 허용된 작업 공간 경로와 네트워크만 접근한다. macOS·Linux·WSL2에서 지원하며, 파일 시스템과 네트워크 접근을 별도로 제한한다. 필요한 경우 샌드박스 밖 실행을 다시 승인받을 수 있다.

## 핵심 요약

권한 수준은 세션의 자율성을 결정하고, 도구·URL·터미널 승인과 샌드박싱은 세부 위험을 제한한다. 자동 승인을 사용할수록 명령과 결과를 검토하고 OS 수준 격리를 함께 적용해야 한다.
