# Workspace Context 개념 요약

- 원문: https://code.visualstudio.com/docs/agents/reference/workspace-context
- 문서 제목: How Copilot understands your workspace
- 원문 수정일: 2026-09-16

## 핵심 개념

Copilot 에이전트는 코드베이스 전체를 이해하려고 검색 도구와 인덱스를 사용한다. 단순히 키워드만 보는 것이 아니라, 코드의 의미와 구조를 파악해 작업에 필요한 관련 정보를 찾는다.

## 1. 검색 및 읽기 도구

에이전트는 다음과 같은 도구를 활용한다.

- Semantic search: 의미 기반 검색
- Text search: 문자열 기반 검색
- Grep: 정규식/문자열 검색
- File search: 파일 이름 탐색
- Usages: 심볼 사용 위치 추적
- List directory: 디렉터리 구조 확인
- Read file: 파일 내용 읽기

이 도구들은 프로젝트 규모와 상황에 따라 자동 선택된다. 작은 프로젝트는 전체 읽기가 가능하고, 큰 프로젝트는 정확히 필요한 부분만 추적한다.

## 2. 의미 기반 검색

`#codebase`는 의미 기반 검색을 수행해, 키워드 일치가 아니라 “관련 코드 찾기”에 강하다.

- 큰 프로젝트에서 특히 유용
- 검색 속도를 위해 semantic index를 사용
- 코드 의미를 해석해 관련 위치를 찾음

## 3. Semantic index의 역할

VS Code는 자동으로 workspace index를 생성한다.

- GitHub 저장소의 경우 GitHub index 사용 가능
- Azure DevOps도 지원 가능
- 로컬 폴더는 자체 인덱스 생성

이 인덱스는 초기에 잠깐 걸릴 수 있지만, 이후에는 빠르게 관련 코드를 찾는 데 도움을 준다.

## 4. 어떤 파일이 포함되나

인덱스는 일반적으로 프로젝트의 관련 텍스트 파일을 포함하되, 다음은 건너뛴다.

- binary 파일
- `.tmp`, `.out` 같은 흔한 불필요 파일
- `.gitignore`로 제외된 파일
- files.exclude 설정에 걸린 파일

## 5. 검색 품질을 높이는 방법

프롬프트를 다음처럼 구체적으로 작성하면 더 좋은 결과를 얻는다.

- “what does this do”보다 “이 함수가 어떤 결제 플로우를 처리하는지”처럼 구체화
- 함수 이름, 클래스 이름, 실제 코드 용어 사용
- 중요 문맥을 직접 추가
- 범위를 제한해서 요청

## 6. 검색 결과 노이즈 줄이기

실제 큰 프로젝트에서는 너무 많은 검색 결과가 오히려 문제를 만든다. 따라서 다음 설정이 매우 중요하다.

- `.gitignore`
- `files.exclude`
- `search.exclude`

이 설정을 잘 구성하면 agent 검색이 더 정확하고 빠르며, 토큰 낭비도 줄어든다.

## 7. Private repositories

프라이빗 저장소를 다룰 때는 추가 권한이 필요할 수 있다. VS Code가 권한을 물어본다.

## 8. 요약

Copilot은 작업을 수행할 때 코드베이스를 “이해”하려고 여러 검색 도구와 인덱스를 이용한다. 이를 통해 개발자가 직접 찾는 방식과 비슷하게 관련 파일과 심볼을 추적할 수 있다. 검색 품질을 높이려면 프롬프트를 구체적으로 쓰고, 불필요한 파일을 제외하는 것이 중요하다.
