# Subagents 요약

- 문서 제목: Subagents in Visual Studio Code
- 원문 수정일: 2026-08-19

## 서브에이전트란

서브에이전트는 주 에이전트가 복잡한 작업의 하위 과제를 위임하는 독립 AI 에이전트다. 조사, 코드 분석, 변경 검토 같은 좁은 작업을 수행하고 결과를 주 에이전트에 보고한다.

깊은 조사 결과를 독립적인 공유 보고서로 만들려면 Research agent를 사용하고, 현재 대화에 결과만 전달할 집중 조사에는 subagent를 사용한다.

## 유용한 상황

- **구현 전 조사**: 라이브러리나 설계 대안을 별도 컨텍스트에서 비교한다.
- **병렬 코드 분석**: 중복 코드, dead code, 오류 처리, 보안을 동시에 점검한다.
- **여러 해법 탐색**: Redis, LRU, 계층형 캐시 같은 대안을 독립적으로 설계하고 비교한다.
- **전문 리뷰**: 보안·성능·접근성 리뷰 에이전트를 병렬 실행한다.
- **다중 모델 합의**: 서로 다른 모델에 같은 문제를 맡겨 결과의 일치·차이를 분석한다.

서브에이전트의 결과 중 최종 요약만 주 에이전트에 돌아오므로 메인 컨텍스트를 오염시키지 않고 토큰 사용을 줄일 수 있다.

## 호출 방식

서브에이전트는 일반적으로 사용자가 직접 호출하기보다 주 에이전트가 필요성을 판단해 호출한다. `agent` 또는 `runSubagent` 도구가 활성화되어 있어야 한다.

기본적으로 서브에이전트는 다음 특성을 가진다.

- 주 대화 기록을 상속하지 않고 프롬프트, 적용 지침, 현재 설정만 받는다.
- 작업이 끝날 때까지 주 에이전트가 결과를 기다린다.
- 여러 서브에이전트를 병렬로 실행할 수 있다.
- 최종 결과만 주 에이전트 컨텍스트에 추가된다.

기본적으로 서브에이전트는 다른 서브에이전트를 호출할 수 없다. `chat.subagents.allowInvocationsFromSubagents`를 켜면 최대 깊이 5까지 중첩할 수 있다.

## Custom agent를 서브에이전트로 사용

Custom agent는 고유 모델, 도구, 지침을 가진 전문 서브에이전트가 될 수 있다. `user-invocable: false`로 사용자 agents 목록에는 숨기고 서브에이전트로만 사용하게 할 수 있다. `disable-model-invocation: true`는 다른 에이전트의 자동 호출을 막는다.

주 에이전트의 frontmatter에 `agents` 목록을 지정하면 사용할 수 있는 서브에이전트를 제한할 수 있다. 이름은 대소문자를 구분하며, 명시적인 목록은 `disable-model-invocation`보다 우선한다.

## 모델 선택

서브에이전트 모델은 다음 우선순위를 따른다.

1. 호출 시 명시한 모델
2. Custom agent frontmatter의 모델
3. 주 에이전트의 모델

서브에이전트에 주 모델보다 비싼 모델을 요청하면 사용할 수 없다.

## 오케스트레이션 패턴

Coordinator agent가 Planner, Architect, Implementer, Reviewer 같은 전문 worker를 순서나 병렬로 조정할 수 있다. 예를 들어 Planner가 계획을 만들고 Architect가 코드베이스와 대조하며, Implementer가 구현하고 Reviewer가 검증하는 흐름을 구성한다.

보안·성능·품질·아키텍처 관점의 병렬 리뷰처럼 각각 독립된 관점을 실행한 뒤 주 에이전트가 우선순위가 있는 통합 결과를 만든다.

## 핵심 요약

서브에이전트는 컨텍스트를 격리한 채 조사·분석·리뷰를 병렬 처리하는 방법이다. 좁은 역할, 명확한 입력과 기대 출력, 적절한 모델·도구 제한을 지정하면 복잡한 작업을 더 효율적으로 오케스트레이션할 수 있다.
