## 튜토리얼 목표

VS Code에서 AI 에이전트를 사용해 개인 포트폴리오 페이지를 만든다. 에이전트는 자연어 요청을 바탕으로 여러 파일을 생성·수정하고, 명령을 실행하며, 오류를 수정한다. 튜토리얼에서는 Agents window에서 시작한 뒤 Chat view로 이동해 같은 세션을 이어가는 흐름을 다룬다.

예제 앱은 HTML, CSS, JavaScript로 구성된 정적 페이지이므로 별도의 런타임이나 빌드 도구가 필요하지 않다.

## 사전 준비

- Visual Studio Code 설치
- VS Code에서 AI 기능 활성화
- Git 설치
- GitHub Copilot 로그인 또는 Copilot Free 등 사용 가능한 플랜 준비

## 프로젝트 폴더 만들기

1. `myportfolio` 폴더를 만든다.
2. 터미널에서 폴더로 이동하고 Git 저장소를 초기화한다.

```bash
cd myportfolio
git init
```

VS Code Source Control 뷰에서 저장소를 초기화해도 된다.

## Agents window에서 기능 만들기

### 에이전트 창 열기

제목 표시줄의 **Open in Agents**를 선택하거나 명령 팔레트에서 `Chat: Open Agents Window`를 실행한다. 로그인 요청이 표시되면 GitHub 계정으로 로그인한다.

### 세션 시작하기

1. 왼쪽 사이드바 상단의 **New**를 선택한다.
2. 작업 공간 드롭다운에서 로컬 `myportfolio` 폴더를 선택한다.
3. 폴더 신뢰 요청이 표시되면 코드를 실행하기 전에 내용을 확인한 후 신뢰 여부를 결정한다.
4. Copilot 에이전트 하니스를 선택한다. Claude, Codex 등 다른 하니스도 지원될 수 있다.
5. 에이전트 역할, 언어 모델, 기본 승인 수준을 검토한다.

다음 프롬프트로 포트폴리오 페이지를 생성한다.

```text
Create a personal portfolio page with HTML, CSS, and JavaScript in separate files. Include a header with my name and a short bio, a section for projects with cards, and a contact section. Use modern styling and add some sample content.
```

에이전트는 요청을 분석하고 파일을 생성·수정한다. 오류가 발생하면 스스로 수정하거나 사용자에게 질문과 승인 요청을 보낸다.

## 통합 브라우저에서 미리 보고 수정하기

1. Agents window의 Files 탭에서 `index.html`을 마우스 오른쪽 버튼으로 클릭하고 **Open in Integrated Browser**를 선택한다.
2. 페이지를 직접 확인하고 상호작용한다.
3. 브라우저의 **Add Element to Chat**을 선택해 요소 선택 모드로 들어간다.
4. 수정할 요소를 선택한다. 선택한 요소의 HTML, CSS와 스크린샷이 프롬프트 컨텍스트로 추가된다.
5. 변경 요청을 입력한다. 예를 들어 `Use a gradient color for the text and use cursive.`처럼 요청할 수 있다.
6. 에이전트가 변경한 뒤 브라우저를 새로 고쳐 결과를 확인한다.

## 변경 사항 검토 및 커밋

1. Changes 패널에서 에이전트가 생성하거나 수정한 파일의 diff를 확인한다.
2. diff에서 특정 코드 블록을 선택해 피드백을 보내고 추가 수정을 요청한다.
3. 변경 드롭다운에서 **Uncommitted Changes**를 선택해 아직 커밋하지 않은 변경을 확인한다.
4. 검토가 끝나면 **Commit Changes**를 선택한다. VS Code가 프롬프트와 변경 내용을 바탕으로 커밋 메시지를 만들 수 있다.

## 편집기에서 세션 계속하기

Agents window의 **Open in Editor**를 선택하면 별도의 편집기 창이 열리고, 오른쪽 Chat view에서 기존 세션을 계속 사용할 수 있다.

다음 프롬프트로 접근성 있고 반응형인 테마 전환 기능을 추가한다.

```text
Add an accessible theme switcher button that toggles between light and dark color themes. Persist the selected theme across page reloads, update the button label to describe the theme it applies, and keep the layout responsive on narrow screens.
```

이후 Source Control에서 diff를 검토하고, 통합 브라우저에서 테마 전환, 버튼 레이블 변경, 좁은 화면의 반응형 레이아웃, 키보드 접근성, 새로 고침 후 테마 유지를 확인한다.

검증에 실패하면 관찰한 결과를 Chat view에 전달하고 수정 및 재검증을 요청한다.

## 핵심 요약

튜토리얼은 에이전트 중심의 작업 방식과 코드 중심의 작업 방식을 하나의 세션으로 연결한다. Agents window에서 큰 작업을 위임하고, 통합 브라우저와 Changes 패널로 결과를 검증한 뒤, 편집기와 Chat view에서 세부 기능을 반복 개선하는 흐름이다.
