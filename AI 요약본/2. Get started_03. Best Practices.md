# Best Practices 요약

- 원문: https://code.visualstudio.com/docs/agents/best-practices
- 문서 제목: Best practices for using AI in VS Code
- 원문 수정일: 2026-08-19

이 문서는 VS Code에서 AI를 더 정확하고 효율적이며 안전하게 사용하는 방법을 정리한다.

## 프로젝트를 AI에 맞게 구성하기

- 프로젝트 전반의 코딩 규칙과 아키텍처를 Custom instructions에 기록한다. Chat에서 `/init`을 입력해 시작 설정을 생성할 수 있다.
- 특정 언어나 폴더에만 적용할 지침은 `applyTo` 패턴으로 범위를 제한한다. `/instructions`로 만들 수 있다.
- 작업에 필요한 도구만 활성화한다. 활성 도구가 적을수록 응답이 빠르고 관련성이 높아진다.
- 생성 파일과 잡음이 많은 파일은 `search.exclude`, `files.exclude`로 검색에서 제외한다.
- 반복되는 전문 작업은 Custom agents와 Skills로 분리하고, 외부 시스템 연결은 Tools와 MCP 서버를 사용한다.

## 작업에 맞는 AI 기능 선택

| 기능 | 적합한 작업 |
| --- | --- |
| Inline suggestions | 코드 작성 중 자동 완성, 변수명, 보일러플레이트 |
| Ask (chat) | 질문, 브레인스토밍, 코드베이스 탐색 |
| Inline chat | 현재 위치에서 함수 리팩터링이나 오류 처리 추가 |
| Agents | 계획과 도구 사용이 필요한 여러 파일 규모의 작업 |
| Plan | 구현 전에 아키텍처나 마이그레이션 계획 수립 |
| Smart actions | 커밋 메시지 생성, 오류 수정, 심볼 이름 변경 같은 단일 작업 |

## 적절한 에이전트 하니스 선택

- 일상적인 코딩에는 로컬 작업 공간과 도구에 접근하는 Copilot을 기본값으로 사용한다.
- 공급자별 기능이 필요하면 Claude 또는 Codex 하니스를 선택한다.
- 팀 검토가 필요하거나 GitHub 이슈를 원격으로 처리하려면 Cloud harness를 사용한다.
- 서로 독립적인 작업은 여러 세션에서 병렬로 실행한다.
- 다음 단계에 더 적합한 대상이 있으면 대화 기록과 컨텍스트를 유지한 채 세션을 hand off한다.

## 효과적인 프롬프트 작성

- 입력, 출력, 제약 조건을 구체적으로 작성하고 언어, 프레임워크, 라이브러리를 명시한다.
- 복잡한 작업은 작고 범위가 분명한 단계로 나눈다.
- 테스트 케이스, 예상 결과, 완료 조건을 프롬프트에 포함한다.
- `make this better`처럼 모호한 표현 대신 성능 개선, null 입력 검증 등 원하는 결과를 직접 말한다.
- 후속 프롬프트로 응답을 다듬고, 잘못된 방향이면 일찍 수정 지시를 보낸다.
- 요구 사항이 모호할 때는 구현 전에 질문하도록 에이전트에게 요청한다.
- 독립적인 작업은 병렬 수행을 요청할 수 있다.

## 적절한 컨텍스트 제공

- 에이전트는 자동으로 코드 검색을 수행하지만, 필요하면 `#<file>`, `#<folder>`, `#<symbol>`로 파일·폴더·심볼을 직접 지정한다.
- 최신 웹 문서는 `#fetch`, 외부 시스템은 MCP 도구로 제공한다.
- 소스 제어 변경 사항, 터미널 출력, 테스트 실패, 이미지와 스크린샷을 컨텍스트로 추가한다.
- 브라우저 도구를 제공하면 에이전트가 사용자 흐름을 실행하고 결과를 검사하며 수정 사항을 검증할 수 있다.

## 모델 선택

- 단순 자동 완성과 보일러플레이트에는 빠른 모델을 사용하고, 계획·디버깅·아키텍처 결정에는 추론에 강한 모델을 사용한다.
- 가능한 경우 최신 모델을 확인한다.
- 프롬프트 파일과 Custom agent에 선호 모델을 고정해 작업별 일관성을 높인다.
- 결과가 만족스럽지 않으면 다른 모델과 비교한다.
- 복잡한 문제는 thinking effort를 높이고, 간단한 문제는 낮춘다.
- BYOK를 사용하면 모델 선택과 호스팅 옵션을 넓힐 수 있다.
- 더 강력한 모델과 긴 컨텍스트는 더 많은 AI credit을 사용할 수 있으므로 비용과 품질을 함께 고려한다.

## 먼저 계획하고 구현하기

여러 파일에 걸친 변경은 계획과 구현을 분리한다.

1. **Explore**: Ask 모드나 subagent로 관련 코드를 읽고 구조를 파악한다.
2. **Plan**: Plan agent로 구조화된 구현 계획을 만들고 검토한다.
3. **Implement**: Agent 모드에서 계획에 따라 구현하고 테스트와 예상 결과를 확인한다.
4. **Review**: Checkpoint로 진행 상황을 검토하고, 방향이 틀리면 되돌리거나 코드 리뷰를 요청한다.

이 흐름은 잘못된 문제를 구현하거나 폐기할 코드에 AI credit을 사용하는 위험을 줄인다.

## AI 결과 검토 및 검증

AI가 생성한 코드는 시작점으로 보고 반드시 검토한다.

- 커밋 또는 병합 전에 코드, 예외 처리, 경계 조건, 숨은 가정을 확인한다.
- 변경 후 테스트를 실행하고, 프롬프트에 테스트 케이스와 예상 결과를 포함한다.
- 문제가 발생하면 Checkpoint로 알려진 정상 상태로 되돌린다.
- 인젝션, 하드코딩된 비밀, 입력 검증 누락 같은 보안 문제를 확인한다.
- 프롬프트에 자격 증명이나 민감한 데이터를 붙여 넣지 않는다.

## 컨텍스트와 세션 관리

- 서로 관련 없는 작업은 새 세션으로 분리한다. 무관한 대화가 쌓이면 응답 품질과 비용에 영향을 준다.
- `/compact`로 긴 대화에서 필요한 정보만 남기고 컨텍스트를 줄인다.
- 반복되는 프롬프트의 앞부분을 안정적으로 유지하면 프롬프트 캐시를 재사용할 수 있다.
- 조사 작업은 subagent로 격리해 주 세션의 컨텍스트 오염을 줄인다.
- 현재 코드의 빠른 작업에는 local, 격리된 백그라운드 작업에는 background, 협업과 pull request에는 cloud 세션을 선택한다.
- 대안 탐색은 `/fork`로 현재 컨텍스트를 보존한 채 분기한다.

## AI credit 사용 최적화

- 단순 작업에는 빠르고 저렴한 모델을, 계획·디버깅·아키텍처 작업에는 고성능 모델을 사용한다.
- 관련 있는 컨텍스트만 보내고 긴 대화는 compact한다.
- 구현 전에 계획해 폐기할 코드에 드는 비용을 줄인다.
- 자동 모델 선택을 사용하면 품질과 비용의 균형을 맞출 수 있다.

## 대규모 코드베이스 작업

- VS Code의 workspace indexing을 활용한다. 대규모 저장소에는 remote indexing을 사용할 수 있다.
- 모노레포나 여러 서비스는 multi-root workspace로 경계를 명확히 한다.
- 프로젝트 아키텍처, 모듈 경계, 팀 규칙처럼 코드만으로 추론하기 어려운 정보를 Custom instructions에 작성한다.
- 독립적인 변경은 병렬 세션으로 나누고, 여러 모듈에 걸친 변경은 Plan agent로 먼저 계획한다.

## 핵심 요약

좋은 결과는 모델의 능력만으로 결정되지 않는다. 프로젝트 지침과 컨텍스트를 정리하고, 작업에 맞는 기능·하니스·모델을 선택하며, 구체적인 프롬프트로 계획부터 검증까지 진행하는 것이 핵심이다. 특히 AI가 만든 결과는 항상 사람이 검토하고 테스트해야 한다.
