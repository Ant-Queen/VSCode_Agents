# Approvals and Permissions 요약

- 원문: https://code.visualstudio.com/docs/agents/run/approvals
- 문서 제목: Manage approvals and permissions
- 원문 수정일: 2026-10-07

## 승인과 샌드박싱

승인은 동작을 자동 실행할지 사용자 확인을 요구할지 결정한다. 샌드박싱은 승인 후에도 지원되는 명령이 접근할 수 있는 파일 시스템·네트워크 범위를 제한한다. 두 제어는 서로 독립적이다.

## 권한 수준

Chat input의 Permissions에서 세션 권한을 설정한다.

- **Manual permissions**: 설정된 도구·URL·터미널 승인 규칙에 따라 필요한 작업을 확인한다.
- **Assisted permissions**: 지원 Agent Host 세션에서 LLM judge가 도구 호출을 평가하고 승인하지 않은 호출은 사용자에게 확인한다. 실험 설정이 필요할 수 있다.
- **Allow all**: 도구 호출을 확인 없이 실행한다.

Autopilot은 권한 수준이 아니라 에이전트 모드다. 모든 도구를 자동 승인하고 오류 재시도와 질문 응답을 통해 완료까지 작업한다. Allow all과 Autopilot은 파괴적 동작도 자동 실행할 수 있다. 샌드박스는 활성 상태라면 이 모드에서도 별도로 적용된다.

## 도구·URL·터미널 승인

`Chat: Manage Tool Approval`에서 도구를 한 번, 세션, 작업 공간, 이후 호출 범위로 승인하고, MCP·확장 도구의 실행 전 승인과 실행 후 결과 검토를 관리한다. 민감한 도구는 `chat.tools.eligibleForAutoApproval`에서 자동 승인을 제외할 수 있다.

URL은 요청을 보내는 승인과 응답 콘텐츠를 모델에 전달하는 승인이 별개다. `chat.tools.urls.autoApprove`에서 URL 패턴별로 각각 설정한다.

`chat.tools.terminal.autoApprove`는 명령별 허용·거부 규칙과 정규식을 설정한다. 복합 명령은 모든 하위 명령이 허용 규칙에 맞아야 자동 승인되며 거부 규칙이 우선한다. 셸 파싱은 best-effort라 완전한 보안 경계가 아니다.

## 핵심 요약

세션 권한은 승인 수준을, 도구·URL·터미널 설정은 개별 호출을, 샌드박스는 명령의 접근 범위를 다룬다. 자동 승인에만 의존하지 말고 최소 권한과 샌드박스를 적용하며 승인 요청의 대상과 매개변수를 살핀다.
