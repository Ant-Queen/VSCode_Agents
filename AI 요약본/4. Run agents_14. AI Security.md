# AI Security 요약

- 원문: https://code.visualstudio.com/docs/agents/run/security
- 문서 제목: AI security in VS Code
- 원문 수정일: 2026-08-19

## 권장 보안 기준선

1. 검토하지 않은 프로젝트는 Restricted Mode로 연다. 신뢰하지 않는 작업 공간에서는 에이전트가 비활성화된다.
2. macOS·Linux·WSL2에서 `chat.agent.sandbox.enabled`를 켜 에이전트 명령의 파일·네트워크 범위를 제한한다.
3. 커밋·병합·pull request 전에 모든 파일 변경을 diff로 검토한다.
4. `chat.tools.edits.autoApprove`에서 `.env` 같은 민감 파일의 자동 편집을 차단한다.
5. 자동 승인은 사용자나 작업 공간 전체보다 현재 세션 범위로 제한한다.
6. MCP 서버를 신뢰하기 전에 출처와 설정을 검토한다.

## 신뢰 경계와 보호 기능

Workspace, 확장 게시자, MCP 서버, 네트워크 도메인은 각각 명시적인 신뢰가 필요한 경계다. 신뢰는 언제든 취소할 수 있다.

VS Code는 다음 보호 기능을 제공한다.

- 기본 에이전트 도구의 작업 공간 제한
- `chat.additionalReadAccessFolders`를 통한 추가 폴더 읽기 권한
- Tools picker를 통한 도구별 활성화
- 세션 단위의 임시 권한
- 과도한 반복 작업을 막는 요청 제한
- Git worktree와 Cloud 실행을 통한 격리
- Secure secrets store와 MCP OAuth 인증
- 승인 대화 상자, diff 검토, warning banner

## 승인과 자동화

Default Approvals는 설정된 승인 규칙을 따르고, Assisted permissions는 LLM judge가 위험을 평가한다. Bypass Approvals는 모든 도구를 자동 승인하며 Agent Host의 Autopilot은 자동 승인과 자율 반복을 결합한다.

터미널은 명령별 자동 승인 규칙을 사용하고, MCP 도구는 세션·작업 공간·사용자 범위로 승인할 수 있다. URL 접근은 도메인 요청 승인과 응답 콘텐츠 검토의 2단계로 처리한다. 자동 승인된 도구와 터미널 명령은 정보 메시지와 관련 설정 링크로 표시될 수 있다.

## Agent sandboxing

Agent sandboxing Preview는 승인 여부와 별개로 OS 수준의 파일 시스템·네트워크 경계를 강제한다. 샌드박스 안의 에이전트 터미널 명령은 제한된 환경에서 실행되므로 자동 승인될 수 있다.

macOS, Linux, WSL2에서 에이전트 터미널 샌드박싱을 사용할 수 있다. 로컬 stdio MCP 서버도 지원 플랫폼에서 샌드박싱할 수 있다. 프롬프트 인젝션이 우려되면 자동 승인 규칙만 의존하지 말고 샌드박싱이나 dev container를 사용한다.

## 주요 보안 위험

### 실행과 접근

에이전트는 사용자의 권한으로 파일을 생성·수정·삭제하고, 명령·스크립트를 실행하고, 사용자의 자격 증명으로 외부 서비스를 호출할 수 있다. 확장과 MCP 서버도 시스템 파일과 외부 리소스에 폭넓게 접근할 수 있다.

### 공급망과 의존성

제3자 MCP 서버, 외부 명령 도구, 배포·업데이트 경로가 취약하거나 악성일 수 있다. MCP Server Trust, 기업 MCP registry, Extension Publisher Trust로 출처를 관리한다.

### 자동 승인

편집·터미널·전체 도구 자동 승인은 검토와 사용자 통제를 약화시킨다. Assisted permissions도 모델 위험 평가가 틀릴 수 있으며 보안 경계가 아니다. 공급자별 위험한 권한 우회 옵션은 샌드박스와 격리 환경에서만 사용한다.

### 정보 노출과 Prompt injection

파일 내용, 터미널 출력, 진단 정보가 모델과 도구에 전달되며 API key·자격 증명·독점 코드가 노출될 수 있다. 신뢰하지 않는 파일, 웹페이지, MCP 출력에 숨은 지침은 에이전트의 결정을 바꾸거나 민감 데이터를 외부로 전송하게 할 수 있다.

## Hooks와 기업 정책

Hooks는 모델이 기억하지 않아도 생명주기 시점에 결정적으로 실행된다. PreToolUse hook으로 위험 명령을 차단하고, allow·deny·ask 결정을 자동화하며, 도구 호출과 파일 변경을 감사 로그로 남길 수 있다.

조직은 ChatAgentMode로 에이전트를 끄고, ChatAgentExtensionTools로 확장 도구를 제한하고, ChatMCP로 MCP 출처를 통제할 수 있다. ChatToolsAutoApprove, ChatToolsEligibleForAutoApproval, ChatToolsTerminalEnableAutoApprove 정책으로 자동 승인과 특정 도구의 수동 승인을 관리한다.

## 핵심 요약

AI 보안은 Workspace Trust, 최소 권한, 변경 검토, 세션 범위 승인, 샌드박싱, MCP·네트워크 신뢰를 함께 적용하는 문제다. 에이전트는 사용자의 권한으로 행동할 수 있으므로 자동화 수준을 높일수록 격리와 검증을 강화해야 한다.
