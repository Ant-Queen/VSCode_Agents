# Plan Work 요약

- 원문: https://code.visualstudio.com/docs/agents/run/planning
- 문서 제목: Plan work with agents in VS Code
- 원문 수정일: 2026-10-07

## 언제 계획을 세울까

접근 방식이 불확실하거나 여러 영역에 걸친 변경이라면 구현 전에 계획을 세워 요구 사항, 영향 파일, 위험, 검증 방법을 확인한다. 작고 명확한 수정은 바로 구현을 요청해도 된다. 일반 대화에서 계획만 요청할 수도 있고, Copilot의 Plan mode 또는 `/plan`으로 전용 계획 흐름을 시작할 수도 있다.

## 계획 작성과 검토

1. 작업 공간을 열고 Copilot 세션을 시작한다.
2. Plan을 선택하거나 `/plan` 뒤에 원하는 결과·제약·검증 기준을 작성한다.
3. 에이전트가 저장소를 조사하고 질문하면 결정 사항을 답한다.
4. Review Plan에서 범위, 프로젝트 패턴, 가정과 미결정 사항, 테스트 계획을 확인한다.
5. 피드백을 제출해 계획을 수정하거나 구현을 승인한다.

계획은 실제 프로젝트의 파일과 기존 패턴을 근거로 해야 한다. **Implement Plan**은 같은 세션에서 구현을 시작하고, **Approve Plan Only**는 계획 승인 후 실행하지 않는다. 세션에 따라 거부 또는 Autopilot 구현 옵션도 제공된다.

## 구현과 별도 세션

계획 승인과 도구 실행 승인은 별개다. 구현을 시작하기 전 세션의 권한을 확인한다. 다른 세션에서 계획을 실행하려면 계획 파일을 저장해 대상 세션에 첨부한다. 계획 모델과 구현 모델을 분리해 비용을 조절할 수도 있다.

## Local 계획 에이전트

Local 세션의 Plan agent는 기본적으로 프로젝트를 읽기 전용으로 조사하고 계획을 session memory의 `/memories/session/plan.md`에 저장한다. Chat: Show Memory Files로 확인하거나 Open in Editor로 편집 가능한 사본을 만든다. Start Implementation은 현재 대화에서 Agent로 전환해 구현을 요청한다.

Local 계획 설정으로 기본 모델, 추가 조사 도구, Agent가 Plan으로 전환할 수 있는지를 조정할 수 있다. 이 설정은 Copilot Plan mode 설정과 구분된다.

## 핵심 요약

Plan mode는 불확실한 변경을 조사·질문·검토한 뒤 실행 가능한 단계와 테스트 기준으로 구체화한다. 구현 전 승인 여부와 권한을 각각 확인하고, 실제 저장소에 맞는 계획인지 검토한다.
