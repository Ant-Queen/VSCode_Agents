# Remote Agent Sessions 요약

- 원문 수정일: 2026-10-07

## 원격 세션 개요

Agents window는 SSH, Dev Tunnel, 브라우저 클라이언트를 통해 원격 머신에서 에이전트 세션을 실행·관리한다. 작업은 코드와 도구가 있는 원격 호스트에서 수행된다. 연결은 Agent Host Protocol을 사용하며, 원격 머신이 켜져 있고 네트워크로 접근 가능해야 한다.

## SSH와 Dev Tunnel

SSH는 접근 가능한 원격 머신에 별도 에이전트 설치 없이 연결한다. 새 세션의 Remote 탭에서 SSH를 선택하고 `user@hostname`을 입력한 뒤 원격 폴더를 고른다.

Dev Tunnel은 원격 호스트에서 먼저 실행해야 한다. Agents window의 Remote > Tunnels에서 계정과 활성 터널, 원격 폴더를 선택한다. 터널은 GitHub 또는 Microsoft 인증을 요구해야 한다. 익명 터널은 URL을 아는 사람이 세션을 만들고 자동 승인 권한으로 명령을 실행할 수 있으므로 사용하지 않는다.

## 원격 호스트 위임

실험 기능으로 현재 Agent Host 세션에서 연결된 원격 호스트를 찾아 새 세션에 작업을 위임할 수 있다. 호스트의 OS·메모리·CPU·모델·세션 부하 등을 고려해 배치하며, 자동 배치라도 대상 호스트와 작업 공간을 승인 전에 검토한다. 원격 도구는 현재 작업 공간을 복사하거나 저장소를 자동 clone하지 않으므로 원격 호스트의 기존 폴더 또는 worktree를 지정한다. 진행 중에는 조정 중인 Agents window 연결을 유지해야 한다.

## 원격 Dev Container와 브라우저

지원되는 SSH·Tunnel·WSL 호스트에서는 실험 기능으로 프로젝트 Dev Container 안에서 Agent Host 세션을 실행할 수 있다. 원격 호스트에 Docker가 실행 중이고 프로젝트에 Dev Container 구성이 있어야 한다.

브라우저 Agents window는 `https://insiders.vscode.dev/agents`에서 사용한다. 호스트에서 Stable은 `code tunnel`, Insiders는 `code-insiders tunnel`을 실행한 뒤 로그인하고 브라우저에서 호스트와 폴더를 고른다. 호스트가 오프라인이면 연결이 끊긴 상태로 표시되고 온라인 복귀 시 재연결된다.

## 핵심 요약

원격 세션은 개발 도구와 코드가 있는 호스트에서 에이전트를 실행하면서 다른 장치에서 관리하게 한다. 터널 인증을 유지하고, 원격 대상·폴더·권한을 확인하며, 실험적 원격 위임은 작업 공간이 자동 복사되지 않는다는 점을 고려한다.
