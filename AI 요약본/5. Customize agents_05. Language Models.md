# Language Models 설정 요약

- 원문: https://code.visualstudio.com/docs/agent-customization/language-models
- 문서 제목: AI language models in VS Code
- 원문 수정일: 2026-08-19

## 채팅 모델 선택

Chat input의 language model picker에서 채팅과 코드 편집에 사용할 모델을 바꾼다. 빠른 모델은 단순 질문과 작은 편집에, reasoning 모델은 리팩터링·아키텍처·다단계 작업에 적합하다. Restricted Mode에서는 Auto만 표시될 수 있다.

## Thinking effort

reasoning 모델의 모델 메뉴에서 Thinking Effort를 선택해 요청별 추론량을 조절한다. 높은 수준은 복잡한 작업의 품질을 높일 수 있지만 thinking token과 AI credit, 지연도 증가시킨다. 선택한 effort는 세션에 기억된다.

## Auto model selection

모델 picker에서 Auto를 선택하면 작업 복잡도와 실시간 모델 상태를 평가해 적합한 모델로 요청을 보낸다. 응답 hover에서 실제 사용 모델을 확인할 수 있다.

## Language Models editor

`Chat: Manage Language Models` 또는 모델 picker의 gear 아이콘으로 editor를 연다. 모델의 기능, 컨텍스트 크기, 과금, 표시 여부를 확인하고 공급자별 그룹을 검색·필터링할 수 있다.

- `@provider:"OpenAI"`
- `@capability:tools`
- `@capability:vision`
- `@capability:agent`
- `@visible:true/false`

eye 아이콘으로 picker 표시 여부를 바꾸고 pin 아이콘으로 즐겨찾기 모델을 고정한다.

## BYOK

BYOK는 호환되는 모델 공급자의 API key, 로컬 모델, 자체 호스팅 endpoint를 VS Code 채팅에 연결한다. GitHub 계정이나 Copilot 플랜 없이도 채팅을 사용할 수 있으며 Ollama 같은 로컬 모델로 오프라인 작업도 가능하다.

Agent Host 세션에서는 `chat.agentHost.byokModels.enabled`가 필요할 수 있다. Semantic search, inline suggestions, embedding 기반 기능은 여전히 GitHub 계정이나 Copilot 플랜을 요구할 수 있다.

모델 추가 방식은 built-in provider, Marketplace의 model provider extension, Custom Endpoint다. API key는 `${input:...}`나 보안 저장소로 관리하고 원문을 커밋하지 않는다.

Custom Endpoint는 Chat Completions, Responses, Anthropic Messages API를 지원하며 모델별 `toolCalling`, `vision`, `maxInputTokens`, `maxOutputTokens`, `modelOptions`, `requestHeaders` 등을 설정할 수 있다. Agent에서 사용할 모델은 tool calling을 지원해야 한다.

## 기능별 모델

`inlineChat.defaultModel`로 Inline Chat 모델을 별도 지정한다. Inline suggestions 모델은 Chat 메뉴의 Configure Inline Suggestions에서 바꾼다. 제목 생성, 요약, 설정 검색, Git review 같은 utility task는 `chat.utilityModel`과 `chat.utilitySmallModel`로 재지정할 수 있다.

## 핵심 요약

Language Models editor는 모델의 기능과 표시를 관리하고, picker에서 작업별 모델과 추론량을 선택하게 한다. BYOK는 선택 폭과 오프라인 사용을 넓히지만 기능·보안·Copilot 의존성이 모델마다 다르므로 API key와 tool calling 지원을 확인해야 한다.
