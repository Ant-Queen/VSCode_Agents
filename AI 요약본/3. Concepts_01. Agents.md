# Agents 개념 요약

- 원문: https://code.visualstudio.com/docs/agents/concepts/agents
- 문서 제목: Understand AI agents
- 원문 수정일: 2026-09-16

## 핵심 개념

에이전트는 단순히 텍스트를 생성하는 모델이 아니라, 작업을 수행하기 위해 도구를 사용하고 결과를 검증하는 AI 시스템이다. VS Code에서는 에이전트가 요청을 받고 관련 컨텍스트를 수집한 뒤, 필요한 도구를 사용해 파일을 읽고 수정하고 테스트를 실행할 수 있다.

## 1. 에이전트 루프(agent loop)

에이전트는 한 번의 응답으로 끝내지 않고 반복적으로 다음 과정을 수행한다.

1. 요청을 받음
2. 관련 컨텍스트를 수집함
3. 도구를 사용해 행동함
4. 결과를 검토하고 다음 동작을 결정함
5. 최종 결과를 사용자가 검토함

이 반복 구조를 agent loop라고 한다. 예를 들어 폼 검증을 추가하는 작업도 우선 관련 코드를 찾고, 수정하고, 테스트를 실행하며, 실패가 있으면 다시 수정하는 흐름을 반복한다.

## 2. 사용자가 여전히 통제한다

에이전트는 자율적으로 행동할 수 있지만, 최종 책임은 사용자에게 있다.

- 어떤 도구를 활성화할지 결정
- 민감한 작업에 승인 요구 설정
- 작업을 중지하거나 방향 전환 가능
- 수정 결과와 검증 결과를 검사하고 반영 여부 결정

## 3. 세션(session)

세션은 에이전트 작업의 단위다. 대화 기록, 작업 상태, 코드 변경 내용, 실행 환경이 하나의 작업 단위로 묶인다.

- 세션은 독립적으로 운영됨
- 여러 작업을 병렬로 수행 가능
- Chat view와 Agents window에서 동일 세션을 이어서 사용 가능
- 다른 에이전트 또는 하니스로 전달 가능

## 4. 하니스(harness)

하니스는 에이전트가 실제로 동작하도록 연결해주는 런타임이다. 모델, 도구, 세션 상태를 함께 관리하며, 작업이 어디서 실행될지 결정한다.

예시:

- Copilot
- Claude
- Codex

하니스는 모델 자체와는 다르다. 모델은 추론을 담당하고, 하니스는 이 추론을 실제 행동으로 연결하는 역할을 한다.

## 5. 확장 기능: Planning, Subagents, Memory, Customization

에이전트는 단순 작업 외에도 다음 기능을 사용할 수 있다.

- Planning: 구현 전에 계획 수립
- Subagents: 복잡한 작업을 별도 하위 에이전트가 맡음
- Memory: 세션/작업 간에 기억 저장
- Customization: 프로젝트별 지침, 커스텀 에이전트, 스킬 등 적용

## 6. 요약

에이전트는 “질문에 답하는 AI”가 아니라, 작업을 수행하고 검증하며 반영 여부를 함께 결정하는 AI 협업 파트너다. VS Code는 세션, 하니스, 도구, 사용자 승인 체계, 커스터마이징을 통해 이 동작을 구조적으로 관리한다.
