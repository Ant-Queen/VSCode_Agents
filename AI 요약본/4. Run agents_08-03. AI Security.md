# AI Security 요약

- 원문: https://code.visualstudio.com/docs/agents/run/security
- 문서 제목: Secure AI-assisted development in VS Code
- 원문 수정일: 2026-10-07

## 권장 보안 기준

1. 신뢰하지 않는 프로젝트는 Workspace Trust의 Restricted Mode에서 먼저 검토한다. 제한 모드에서는 에이전트를 사용할 수 없다.
2. 지원되는 호스트에서는 agent sandboxing을 활성화하고 네트워크 접근도 별도로 제한한다. 샌드박스의 외부 네트워크는 기본 허용일 수 있다.
3. 파일 변경을 diff로 검토한 뒤 커밋·merge·PR에 통합한다.
4. `.env` 등 민감 파일은 편집 전 승인을 요구하도록 설정한다.
5. 도구와 터미널 자동 승인은 전역보다 세션 범위로 제한한다.
6. MCP 서버와 저장소의 MCP 설정을 검토하고 신뢰할 수 있는 출처만 허용한다.

## VS Code의 보호 장치

작업 공간 범위의 파일 접근, 도구 선택, 세션 권한, Git worktree, Cloud 실행 격리, 요청 제한 및 자격 증명 저장소 등이 위험 범위를 줄인다. 승인 기능은 도구·URL·터미널 작업에 확인을 요구하고, diff 검토는 변경을 통합하기 전에 확인하도록 한다. 지원되는 Agent Host에서는 샌드박스가 명령과 자식 프로세스를 OS 수준으로 격리한다.

각 제어에는 한계가 있다. worktree는 명령·네트워크 제한이 아니고, 터미널 자동 승인 규칙은 셸 구문 분석이 완벽하지 않다. 샌드박스는 VM이나 계정 경계가 아니며 자격 증명·개발 캐시·허용 네트워크가 노출 범위를 넓힐 수 있다. 고위험 작업은 샌드박스와 함께 Dev Container 같은 추가 경계를 고려한다.

## 주요 위험과 대응

프롬프트 인젝션은 코드·문서·웹·도구 결과에 숨은 지시로 에이전트 행동을 유도할 수 있다. 출처가 불분명한 입력과 도구 결과를 검토하고, 필요한 도구만 제공하며 URL의 요청과 응답 승인을 구분한다. 공급망·의존성 위험은 프로젝트와 MCP 서버의 출처·설정을 확인한다. 정보 노출은 민감 정보 접근을 제한하고 비밀이 포함된 파일의 자동 편집 승인을 막는다.

Hooks는 `PreToolUse` 등 결정적 제어로 위험 도구 호출을 허용·거부·확인하도록 하고 감사 로그를 남길 수 있다. 조직은 정책으로 에이전트, 확장 도구, MCP 서버, 자동 승인과 특정 도구 권한을 제한할 수 있다.

## 핵심 요약

AI 보안은 신뢰 경계, 최소 권한, 샌드박싱, 변경 검토를 함께 적용하는 다층 접근이다. 자동 승인이나 단일 격리 기능을 완전한 보안 경계로 간주하지 말고, 프로젝트와 도구의 출처 및 네트워크·자격 증명 접근을 함께 관리한다.
