# Agent Host Architecture 요약

- 원문: https://code.visualstudio.com/docs/agents/concepts/agent-host
- 문서 제목: Understand the VS Code Agent Host
- 원문 수정일: 2026-10-07

## Agent Host의 필요성

VS Code는 agent 로직을 별도 프로세스인 Agent Host에서 실행한다. 이유는 다음과 같다.

- 여러 클라이언트가 같은 세션을 공유할 수 있음
- 원격 실행이 가능함
- 에디터가 닫혀 있어도 세션이 계속 유지될 수 있음
- 여러 agent 구현체를 공통 인터페이스로 관리 가능
- 긴 실행 작업이 확장 호스트를 막지 않음

기존에는 에이전트 로직이 확장 호스트 안에서 동작했지만, 이제는 Agent Host가 전용 런타임 역할을 맡는다.

## 프로세스 구조

Agent Host는 로컬 유틸리티 프로세스 또는 원격 서버 형태로 실행될 수 있다.

- 로컬 IPC: 로컬 통신
- AHP JSON-RPC over WebSocket: 원격 통신

Agent Host는 세션을 소유하고, 클라이언트는 이를 표시하고 제어하는 역할을 맡는다.

## AHP(Agent Host Protocol)

Agent Host Protocol은 호스트와 클라이언트 간의 표준 통신 프로토콜이다.

특징:

- JSON-RPC 기반
- 상태를 순차적 액션으로 동기화
- 세션, 채팅, 터미널, 변경 집합 등 리소스를 URI로 관리
- 연결이 끊겨도 재접속 시 상태를 복구할 수 있음

## 클라이언트와 도구

Agent Host는 자체적으로 세션과 워크스페이스 관리 기능을 갖고 있다. 하지만 브라우저 도구 같은 클라이언트 제공 도구도 연결될 수 있다.

이 경우 Agent Host는 해당 도구를 세션에 추가하고 호출 결과를 다시 전달한다.

## 로컬/원격 호스트

Agent Host는 다음 위치에서 실행될 수 있다.

- 현재 머신
- SSH 연결 호스트
- Tunnel 연결 호스트
- WSL 호스트
- Dev Container

대부분의 UI는 클라이언트에 있지만, 실제 작업은 Agent Host가 실행 중인 곳에서 수행된다.

## 확장 호스트와 차이점

에이전트 session이 Agent Host에서 실행될 때와 확장 호스트에서 실행될 때 동작 차이가 있다.

예:

- 리뷰 방식
- 사용자 지정 파일 위치
- 훅 구현 방식
- Autopilot 의미
- 멀티 세션, 다중 채팅, 원격 호스팅 지원 여부

## 핵심 요약

Agent Host는 VS Code에서 에이전트를 안정적으로 운영하기 위한 전용 런타임이며, 세션 상태, 원격 실행, 작업 지속성, 클라이언트-호스트 분리를 가능하게 한다. 결과적으로 에이전트는 에디터 창이 닫혀 있어도 계속 동작할 수 있고, 여러 클라이언트가 같은 작업을 제어할 수 있게 된다.
