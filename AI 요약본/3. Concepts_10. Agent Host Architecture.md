# Agent Host Architecture 개념 요약

- 원문: https://code.visualstudio.com/docs/agents/concepts/agent-host
- 문서 제목: Understand the VS Code Agent Host
- 원문 수정일: 2026-09-16

## 핵심 개념

VS Code의 에이전트는 별도의 프로세스인 Agent Host에서 동작한다. 이 구조는 에이전트 세션을 UI 클라이언트와 분리하여 더 안정적이고 유연하게 운영하기 위해 설계되었다.

## 1. 왜 Agent Host가 필요한가

기존 방식에서는 에이전트가 extension host 안에서 동작했지만, 이는 작업의 긴 지속성과 자율성에 한계가 있었다.

Agent Host는 다음 장점을 제공한다.

- 여러 클라이언트가 같은 세션을 보고 제어 가능
- 원격 실행 가능
- 에디터가 종료되어도 세션이 계속 실행될 수 있음
- 여러 에이전트 구현을 공통 인터페이스로 연결 가능
- 긴 작업을 별도 프로세스에서 수행해 UI나 확장 프로그램의 부하를 줄임

## 2. 아키텍처 구조

Agent Host는 로컬 유틸리티 프로세스로 동작할 수도 있고, 원격 머신에서 서버 형태로 동작할 수도 있다.

- 로컬 IPC 또는 WebSocket 기반 통신 사용
- 세션, 채팅, 터미널, 변경 사항 같은 자원을 URI 단위로 공유
- host가 상태의 정합성을 유지함
- 클라이언트는 이를 조회하고 제어하는 역할만 수행

## 3. Agent Host Protocol (AHP)

AHP는 호스트와 클라이언트 간의 공용 프로토콜이다.

- JSON-RPC 기반 통신
- 불변 상태와 reducer를 사용해 세션 정보를 동기화
- 연결이 끊어지면 재접속 후 누락된 상태를 복구 가능

즉, 에이전트와 클라이언트 간 상태를 안전하게 동기화한다.

## 4. 클라이언트는 뷰어이자 컨트롤러

Agent Host는 세션의 진짜 소유자다. 클라이언트는 화면을 보여주고 사용자 입력을 전달하는 역할을 한다.

- 에디터, Agents window, 브라우저는 클라이언트일 뿐
- Agent Host가 세션을 관리하고 작업을 이어감
- 작업이 백그라운드에서 계속 실행될 수 있음

## 5. 로컬/원격 실행

Agent Host는 다음 위치에서 동작할 수 있다.

- 로컬 머신
- SSH 연결 호스트
- WSL 환경
- Dev Container
- 브라우저 기반 클라이언트가 연결하는 원격 Host

특히 Dev Container에서는 코드와 도구를 컨테이너 안에서 실행하되, UI는 클라이언트에서 유지한다.

## 6. 기존 extension host와의 차이

일부 세션은 Agent Host 대신 extension host에서 동작할 수도 있지만, Agent Host 기반 세션은 다음에서 차이를 가진다.

- 세션이 여러 창에서 공유 가능
- 여러 채팅을 같은 세션에 가질 수 있음
- 원격 호스팅 가능
- 사용자 수준 customization 경로가 다름
- 일부 확장 도구가 클라이언트에만 제공되는 구조

## 7. 요약

VS Code의 Agent Host는 에이전트 실행을 독립적인 프로세스로 분리하여, 세션 관리, 원격 실행, 다중 클라이언트 동기화, 장기 작업 지원을 가능하게 한다. 이를 통해 에이전트는 UI와 무관하게 계속 작업을 진행할 수 있고, 사용자 흐름을 더 안정적으로 유지할 수 있다.
