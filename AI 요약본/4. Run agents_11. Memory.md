# Memory 요약

- 원문: https://code.visualstudio.com/docs/agents/run/memory
- 문서 제목: Memory in VS Code agents
- 원문 수정일: 2026-08-19

## Memory의 역할

Memory는 에이전트가 여러 대화에 걸쳐 사용자 선호, 이전 작업에서 얻은 교훈, 저장소 지식을 재사용하게 한다. memory tool은 현재 Preview 기능이다.

`chat.tools.memory.enabled` 설정으로 memory tool 사용 여부를 켤 수 있다. 자연어로 "우리 팀은 모든 커밋 메시지에 conventional commits를 사용한다고 기억해"처럼 요청하면 에이전트가 적합한 범위에 메모를 저장하거나 갱신한다.

## Memory 범위

| 범위 | 경로 | 유지 기간 | 용도 |
| --- | --- | --- | --- |
| User | `/memories/` | 세션·작업 공간을 넘어 유지 | 개인 선호, 패턴, 자주 쓰는 명령 |
| Repository | `/memories/repo/` | 같은 작업 공간에서 유지 | 코드 규칙, 구조, 빌드·테스트 명령 |
| Session | `/memories/session/` | 현재 대화가 끝날 때까지 | 작업별 임시 컨텍스트, 진행 중 계획 |

User memory의 처음 200줄은 새 세션 시작 시 자동으로 로드된다. Repository memory는 현재 작업 공간에 한정되고, Session memory는 대화가 끝나면 삭제된다.

## 저장과 조회

저장할 내용은 자연어로 요청한다. 새 대화에서 관련 정보를 물으면 에이전트가 memory 파일을 확인한다. VS Code의 `Chat: Show Memory Files` 명령으로 모든 범위의 파일을 열 수 있다.

`Chat: Clear All Memory Files`는 모든 범위의 memory 파일을 삭제한다. 개별 파일 삭제 명령은 아직 지원되지 않으므로, 특정 메모를 바꾸려면 에이전트에 해당 메모를 갱신하도록 요청한다.

## Copilot Memory

Copilot Memory는 VS Code memory tool과 별개의 GitHub 호스팅 시스템이다. 저장소별 통찰을 cloud agent, code review, CLI 등 여러 Copilot 표면에서 공유한다.

사용하려면 VS Code의 `chat.copilotMemory.enabled`와 GitHub 저장소의 Copilot Memory를 모두 활성화해야 한다. 조건이 충족되지 않으면 Repository memory는 로컬에 저장된다.

Copilot Memory는 기여자가 만든 저장소 범위 메모리를 검증한 뒤 사용하고, 오래된 정보는 28일 후 자동 만료한다. 개인·세션 메모리는 로컬에 남으며 Copilot Memory로 이동하지 않는다.

## Memory tool과 Copilot Memory 비교

- Memory tool은 사용자가 요청하거나 에이전트가 작성하며 User, Repository, Session 범위를 지원한다.
- Copilot Memory는 Copilot 에이전트가 자동으로 만들고 Repository 범위만 지원한다.
- Memory tool은 기본적으로 로컬이고, Copilot Memory는 GitHub에 저장된다.
- Copilot Memory는 여러 Copilot 표면에서 공유되지만 기본적으로 opt-in이다.

## 핵심 요약

Memory는 반복되는 프로젝트 지식과 선호를 다시 설명하는 비용을 줄인다. 개인 정보는 User 범위에, 저장소 규칙은 Repository 범위에, 현재 작업의 임시 정보는 Session 범위에 저장하고, 여러 Copilot 제품 간 공유가 필요할 때만 Copilot Memory를 활성화한다.
