## 세션이란

세션은 에이전트와의 작업 단위를 의미한다. 하나의 세션에는 워크스페이스, 코드 변경, 실행 상태, 대화 이력이 함께 포함된다.

세션은 하나 이상의 채팅을 가질 수 있고, 각 채팅은 서로 독립적인 대화 기록을 가진다.

## 채팅과 세션의 관계

- 세션: 작업 단위 전체
- 채팅: 세션 안에서 이루어지는 개별 대화

같은 세션 안에서도 여러 채팅을 열어, 예를 들어 기능 구현용 채팅과 테스트 작성용 채팅을 동시에 운영할 수 있다. 다만 각 채팅은 다른 채팅의 대화 기록을 자동 상속하지 않는다.

## 새 채팅, 포크, 새 세션의 선택

세션 안에서 이어서 작업할지, 포함된 대화 기록을 유지할지, 아니면 완전히 독립된 작업으로 분리할지에 따라 선택이 달라진다.

- 새 채팅: 같은 세션 안에서 관련 작업을 이어감
- 포크: 기존 대화의 흐름을 유지하면서 대체 경로 탐색
- 새 세션: 다른 작업, 다른 워크스페이스, 다른 실행 환경을 시작

## 교차 화면에서의 세션

에이전트 호스트 세션은 Chat view와 Agents window에서 계속 이어서 관리할 수 있다. 화면을 전환해도 세션 자체는 유지된다.

또한 다른 애플리케이션에서 만든 세션을 발견해서 이어붙일 수도 있다.

## 핸드오프

작업을 더 적합한 모델, harness, 실행 환경, 역할로 넘길 수 있다. 이를 핸드오프라고 한다.

예시:

- Copilot 세션을 Claude나 Codex로 이어가기
- Plan agent를 통해 설계 후 구현 agent로 넘기기
- 클라우드 환경에서 실행되도록 이동하기

## 원격 및 동기화 세션

세션은 로컬 머신에서만 돌아가는 것이 아니라, 원격 호스트, Dev Container, 클라우드 환경에서도 동작할 수 있다. 세션 기록은 GitHub 계정과 동기화되거나 다른 장치에서 다시 이어볼 수 있다.

## 채팅 종료와 완료 처리

- 채팅 닫기: 대화는 숨기지만 보관
- 완료 표시: 작업 완료로 처리하되 기록 유지
- 삭제: 대화 삭제, 복구 불가

## 핵심 요약

세션은 에이전트의 작업 단위이며, 채팅은 그 안의 독립 대화다. VS Code는 관련 작업을 같은 세션에서 묶거나, 반복 작업은 포크와 새 세션으로 분리할 수 있게 설계되어 있어 대규모 작업을 체계적으로 관리할 수 있다.
