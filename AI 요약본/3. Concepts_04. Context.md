## 컨텍스트란

컨텍스트는 모델이 응답을 생성할 때 볼 수 있는 모든 정보다. 대화 기록, 작업 공간 파일, 도구 출력, 사용자 정의 지침과 사용자가 명시한 참조가 포함된다.

모델은 제공된 컨텍스트 밖의 정보를 알 수 없으므로, 관련 파일과 명확한 지침을 포함한 집중된 프롬프트가 모호한 프롬프트보다 좋은 결과를 만든다. 새 세션은 이전 세션의 대화나 컨텍스트를 자동으로 이어받지 않는다.

## VS Code가 컨텍스트를 구성하는 방식

VS Code는 요청마다 다음 요소를 조합해 모델 프롬프트를 만든다.

- 시스템 지침
- Custom agents, skills, custom instructions 같은 맞춤화
- 현재 사용자 메시지
- 현재 세션의 대화 기록
- 활성 파일, 선택 영역, 오류, Git 상태 같은 암시적 컨텍스트
- `#` 멘션으로 추가한 파일, 편집기 컨텍스트, 웹 콘텐츠
- 파일 읽기, 터미널, 코드베이스 검색 결과 같은 도구 출력

현재 작업과 무관한 정보는 모델에 보이지 않으며, 특정 파일을 명시적으로 참조하면 모델이 올바른 대상을 파악하기 쉬워진다.

## 작업 공간 인덱싱

VS Code는 코드베이스에서 관련 코드를 빠르게 찾기 위해 인덱스를 사용한다.

- **원격 인덱스**: GitHub 저장소에서 GitHub가 관리한다.
- **로컬 인덱스**: 로컬 컴퓨터에 semantic index를 저장한다.
- **기본 인덱스**: semantic indexing을 사용할 수 없을 때 단순한 검색 알고리즘을 사용한다.

일반적으로 프로젝트의 관련 텍스트 파일을 인덱싱하며, `.gitignore`와 `files.exclude`로 제외된 파일, 바이너리 파일은 제외한다. 로컬 작업 공간의 초기 인덱스 생성에는 시간이 걸릴 수 있고, 명령 팔레트의 `Build Codebase semantic index` 명령으로 다시 만들 수 있다.

## 검색 도구

에이전트는 요청에 따라 여러 검색 도구를 조합한다.

- semantic search: 의미를 기준으로 코드를 찾는다.
- text search와 grep: 정확한 텍스트나 정규식을 찾는다.
- file search: 파일 이름이나 glob으로 찾는다.
- usages: 심볼의 참조와 구현을 추적한다.
- list directory와 read file: 구조를 확인하고 파일을 읽는다.

semantic search가 준비되지 않아도 나머지 검색 도구로 대부분의 작업을 수행할 수 있다.

## 효과적인 컨텍스트 사용

- 새 작업은 새 세션에서 시작한다.
- 전체 코드베이스보다 관련 파일과 심볼만 명시한다.
- 프로젝트 전체 규칙은 Custom instructions에 저장한다.
- 함수명, 클래스명, 정확한 개념을 프롬프트에 사용한다.
- 선택한 코드, 파일, 오류, 터미널 출력 등 필요한 정보를 수동으로 추가한다.
- 코드가 아닌 외부 정보는 fetch 도구나 MCP 서버를 사용한다.

`#codebase`를 직접 입력하지 않아도 에이전트는 필요할 때 semantic search를 자동으로 사용할 수 있다. 다만 특정 요청에서 semantic search를 강제하려면 `#codebase`를 추가할 수 있다.

## 핵심 요약

좋은 에이전트 결과는 모델에 전달되는 컨텍스트의 품질과 범위에 크게 좌우된다. VS Code의 자동 검색과 인덱싱을 활용하되, 프롬프트에는 작업에 직접 필요한 파일·심볼·규칙만 명확하게 추가하는 것이 효과적이다.
