## 컨텍스트란

컨텍스트는 에이전트와 언어 모델이 작업을 수행할 때 참고하는 정보 전체를 의미한다. 대화 기록, 작업 영역 파일, 도구 결과, 사용자 지정 지침, 직접 참조한 파일과 문서 등이 포함된다.

모델은 이 정보 안에서 다음 행동을 결정한다. 컨텍스트가 적절할수록 더 정확하고 관련성 높은 결과를 낸다.

## VS Code가 컨텍스트를 조립하는 방식

에이전트가 모델에 요청을 보낼 때마다 VS Code는 여러 소스를 합쳐 프롬프트를 구성한다.

- 시스템 지침
- 사용자 지정 설정
- 현재 사용자 메시지
- 현재 채팅의 대화 기록
- 암묵적 컨텍스트(활성 파일, 선택된 텍스트, 오류, git 상태)
- 명시적 참조(선택한 파일·심볼·웹 페이지)
- 도구 호출 결과

## 워크스페이스 인덱싱

VS Code는 의미 기반 검색을 위해 워크스페이스 인덱스를 유지한다. 이를 통해 코드베이스에서 "의미"에 맞는 관련 파일을 빠르게 찾을 수 있다.

인덱스가 아직 준비되지 않았더라도, 텍스트 검색, 파일 검색, 언어 인텔리전스를 활용해 충분히 작업을 진행할 수 있다.

## 암묵적 컨텍스트와 명시적 컨텍스트

암묵적 컨텍스트는 현재 열린 파일, 선택 영역, 에러, 현재 편집 상태처럼 자동으로 드러나는 정보다.

명시적 컨텍스트는 `#` 로 선택한 파일, 문서, 심볼, 웹 페이지 등으로 추가하는 정보다. 중요한 소스를 명시하면 에이전트가 불필요한 탐색을 줄이고 정확도를 높인다.

## 컨텍스트 윈도우와 압축

모델은 처리 가능한 최대 정보량이 정해져 있다. 이 범위를 컨텍스트 윈도우라고 한다.

대화가 길어지면 VS Code는 오래된 내용을 요약해 압축한다. 이와 동시에 일부 세부 내용은 생략되거나 요약될 수 있다. 필요한 경우 `/compact` 로 수동 압축을 수행할 수 있다.

## 서브에이전트와 컨텍스트 격리

서브에이전트는 메인 대화의 전체 컨텍스트를 모두 가져가는 대신, 자신만의 좁은 컨텍스트에서 일을 수행하고 결과를 반환한다. 이 방식으로 메인 대화의 노이즈를 줄일 수 있다.

핵심은 컨텍스트 격리이며, 코드 변화가 완전히 분리되는 것은 아니다. 실제 파일 접근과 권한은 실행 환경과 허용 범위에 따라 결정된다.

## 좋은 컨텍스트 관리 팁

- 작업 목표와 제약 조건을 분명히 설명한다.
- 전체 코드베이스를 한 번에 붙이지 않고 필요한 부분만 참조한다.
- 중요한 파일이나 오류, 문서를 명시적으로 추가한다.
- 서로 무관한 작업은 별도 세션으로 분리한다.

## 핵심 요약

컨텍스트는 에이전트가 "무엇을 알고 있는지"를 결정한다. VS Code는 대화 기록, 파일, 검색 결과, 선택 영역, 도구 출력 등을 조합해 모델이 좋은 판단을 하도록 돕고, 긴 대화를 관리하기 위해 압축과 서브에이전트 기반 분리를 사용한다.
