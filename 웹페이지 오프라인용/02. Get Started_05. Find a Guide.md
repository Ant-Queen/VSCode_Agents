## 가이드 선택

이 문서는 VS Code 에이전트를 처음 배우는 사용자와 실제 코드베이스에 적용하려는 사용자를 위해 튜토리얼·가이드를 작업 목적별로 안내한다. 샘플 프로젝트를 따라가거나, 자신의 저장소에서 바로 시작할 수 있다.

가이드를 고를 때는 다음을 먼저 확인한다.

- **프로젝트**: 샘플 프로젝트를 만드는지, 빌드·테스트가 준비된 기존 저장소가 필요한지 확인한다.
- **하니스**: 가이드에서 사용하는 도구와 사용자 지정 형식이 현재 에이전트 하니스와 맞는지 확인한다. 같은 언어 모델을 선택해도 하니스별 도구와 설정 형식은 서로 다를 수 있다.
- **인터페이스**: Chat view를 사용하는지 Agents window를 사용하는지 확인한다. Chat view는 현재 작업 공간에서 코드와 협업하는 데, Agents window는 여러 프로젝트의 세션을 조정하는 데 적합하다.

## 기존 에이전트 사용자를 위한 빠른 시작

자신의 저장소에서 작업할 때 권장되는 흐름은 다음과 같다.

1. 저장소를 VS Code 작업 공간으로 연다.
2. 기존 개발 흐름과 세션의 관계를 파악하고, 선택한 하니스의 계정·환경 요구사항을 충족하는지 확인한다.
3. 코드 탐색처럼 변경이 없는 제한된 작업부터 시작하거나, 개발 환경과 테스트가 준비된 상태에서 작은 기능을 구현한다.
4. 변경된 코드와 테스트 결과를 검토하고 직접 검증한 뒤 통합한다.
5. 첫 작업을 마친 후 프로젝트 지침이나 에이전트 설정을 적용한다.

처음에는 가이드가 제시하는 권장 세션 설정을 유지한다. 다른 하니스로 바꿀 때는 도구 이름과 사용자 지정 파일을 조정해야 할 수 있다.

## 작업 목적에 맞는 가이드

- 코드 동작을 따라가며 이해하기: 코드베이스 탐색
- 요구사항을 조사·계획·구현·검증하기: 기능 추가
- 재현 가능한 오류를 테스트와 함께 수정하기: API 버그 수정
- 동작을 유지하면서 코드 구조 바꾸기: 안전한 리팩터링
- 노트북 생성·편집·실행: Jupyter 노트북 작업
- 기존 코드에 테스트 추가: AI로 테스트 작성
- 브라우저에서 웹 앱 동작 확인: Browser Tools 기반 테스트
- 테스트 우선 개발 프로세스 구성: TDD 설정
- 프로젝트 지침·스킬·전문 에이전트 적용: 프로젝트 맞춤화
- 독립적인 작업을 Git worktree에서 병렬 수행: 병렬 작업 실행

## 접근성 및 조직 환경

관리 장치에서는 조직 정책이 사용 가능한 에이전트와 공급자를 제한할 수 있다. 사용할 수 있는 에이전트가 보이지 않으면 조직 설정과 문제 해결 안내를 확인한다. 키보드, 스크린 리더, 저시력 사용자는 VS Code의 접근성 기능을 함께 활용할 수 있다.

## 핵심 요약

가이드의 샘플·저장소 요구사항, 하니스, 인터페이스가 현재 환경과 맞는지 확인한 뒤 목적에 맞는 작은 작업을 선택한다. 실제 저장소에서는 변경을 검토하고 테스트한 후 반영하며, 조직 정책과 접근성 요구사항도 고려한다.
