# Diagnose Prompt Caching 요약

- 원문: https://code.visualstudio.com/docs/agents/agent-troubleshooting/cache-explorer
- 문서 제목: Diagnose prompt caching with the Cache Explorer
- 원문 수정일: 2026-08-19

## Prompt caching

Prompt caching은 이전 요청과 동일한 prefix를 재사용해 지연 시간과 token 비용을 줄인다. 첫 divergence 이후의 나머지 요청은 cache miss가 되므로 초반 system instruction이나 도구 정의의 변경이 큰 영향을 준다.

## Cache Explorer 사용

Agent Debug Logs의 Summary에서 Cache Explorer를 열어 연속 모델 turn을 비교한다. 각 turn에서 cache hit 비율, 시간, 모델명, timestamp를 확인하고 Prompt signature에서 system instruction·tool definition·message별 첫 divergence 위치를 확인한다.

## Cache miss 원인과 개선

모델, thinking effort, context 크기, 도구, MCP 설정을 세션 중 변경하면 cache가 재구성될 수 있다. 안정적인 지침을 대화 앞부분에 두고 자주 바뀌는 파일·터미널 출력은 뒤에 추가한다.

탐색 작업은 subagent로 격리하고, 긴 중단 후에는 새 세션이나 `/compact`를 사용해 불필요한 초기 context를 줄인다.

## 핵심 요약

Cache Explorer는 프롬프트의 어느 지점에서 공통 prefix가 달라져 cache miss가 발생하는지 보여준다. 안정적인 설정과 지침을 유지하고 변동이 큰 context를 뒤로 배치하면 비용과 응답 지연을 줄일 수 있다.
