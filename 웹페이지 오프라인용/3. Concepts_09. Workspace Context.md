# Workspace Context 요약

- 원문: https://code.visualstudio.com/docs/agents/reference/workspace-context
- 문서 제목: How Copilot understands your workspace
- 원문 수정일: 2026-08-19

## 작업 공간을 이해하는 방식

Copilot 에이전트는 코드베이스 전체를 검색해 구성 요소 간 연결을 파악하고, 실제 코드에 근거한 답변과 변경을 제공한다. 작업 공간이 몇 개 파일이든 수십만 개 파일이든 요청에 필요한 검색 도구를 조합한다.

요청을 받으면 에이전트는 필요한 정보를 분석하고 여러 검색을 수행한 뒤 결과를 검토한다. 예를 들어 결제 서비스의 오류 처리를 추가할 때 의미 검색, 텍스트 검색, 심볼 사용처 추적, 관련 설정·테스트 파일 검색과 파일 읽기를 차례로 수행할 수 있다.

## 검색 및 읽기 도구

- **Semantic search (`#codebase`)**: 질문의 의미와 일치하는 코드를 찾는다. 작업 공간 인덱스가 필요하다.
- **Text search**: 특정 키워드가 포함된 파일을 찾는다.
- **Grep**: 정확한 텍스트나 정규식을 검색한다.
- **File search**: 파일 이름이나 glob 패턴으로 찾는다.
- **Usages**: 심볼의 참조, 구현, 정의를 추적한다.
- **List directory**: 폴더 구조를 확인한다.
- **Read file**: 관련 파일의 내용을 읽는다.

## Semantic index

VS Code는 작업 공간의 관련 텍스트 파일을 semantic index에 저장해 의미 기반 검색을 빠르게 한다.

- GitHub 저장소는 GitHub가 원격 인덱스를 관리한다.
- Azure DevOps 저장소는 Microsoft 계정으로 인덱스를 사용한다.
- 그 밖의 로컬 작업 공간은 VS Code가 로컬 인덱스를 만들고 백그라운드에서 갱신한다.

인덱스는 일반적으로 관련 텍스트 파일을 포함하며, 바이너리 파일과 `.gitignore` 또는 `files.exclude`로 제외된 파일은 포함하지 않는다. 파일 수가 많으면 최초 생성에 시간이 걸릴 수 있다. 명령 팔레트에서 `Build Codebase semantic index`로 인덱스를 만들거나 다시 만들 수 있다.

## 검색 품질을 높이는 방법

- `this`처럼 모호한 표현 대신 함수명, 클래스명, 도메인 용어를 사용한다.
- 관련 파일을 선택하거나 `#` 멘션으로 파일과 컨텍스트를 직접 추가한다.
- 요청 범위를 명확히 지정한다. 전체 코드베이스의 정확한 호출 횟수 같은 질문은 한 번의 넓은 검색으로 해결되지 않을 수 있다.
- 외부 정보나 기여자 정보처럼 코드 검색으로 알 수 없는 내용은 적절한 도구나 MCP 서버를 사용한다.
- 검색 결과가 너무 많다면 `files.exclude`, `search.exclude`, `.gitignore`로 생성물과 잡음이 많은 파일을 제외한다.

## 자동 검색과 `#codebase`

`#codebase`를 입력하지 않아도 에이전트는 필요할 때 semantic search를 자동으로 사용한다. 특정 요청에서 의미 검색을 강제하고 싶을 때만 `#codebase`를 명시하면 된다.

Semantic index가 아직 준비되지 않았더라도 text search, grep, file search, language intelligence를 사용해 작업을 수행할 수 있다. 따라서 인덱스가 없는 초기 상태에서도 대부분의 코드 탐색은 가능하다.

## 비공개 저장소

비공개 저장소에서 semantic search를 사용하려면 추가 권한이 필요할 수 있다. VS Code가 시작 시 권한을 요청하며, 승인한 정보는 이후 안전하게 저장된다.

## 핵심 요약

Copilot은 자동으로 검색 도구를 선택하고 작업 공간 인덱스를 활용해 코드에 근거한 답변을 만든다. 정확한 코드 용어와 좁은 범위, 관련 파일 참조를 사용하면 검색 결과와 에이전트의 판단 품질을 높일 수 있다.
