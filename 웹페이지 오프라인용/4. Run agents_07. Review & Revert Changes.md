# Review and Revert Changes 요약

- 원문: https://code.visualstudio.com/docs/agents/run/review-code-edits
- 문서 제목: Review and revert agent changes
- 원문 수정일: 2026-08-19

## 변경 사항 검토

에이전트는 세션 폴더나 격리된 Git worktree에 변경을 직접 적용하고 저장한다. Agent Host 세션에서는 각 편집을 Keep 또는 Undo로 승인하는 pending 상태가 없으므로 일반적인 diff, Source Control, pull request 흐름으로 검토한다.

Chat view와 Agents window 모두에서 변경 파일을 열어 diff를 확인할 수 있다. `chat.checkpoints.showFileChanges`를 켜면 요청별 파일 목록과 변경 통계를 보고, multi-file diff를 열 수 있다. diff의 특정 범위에 피드백을 남기거나 후속 프롬프트와 직접 편집으로 수정한다.

## 검증과 통합

변경 사항을 커밋하기 전에 테스트, 디버거, 관련 편집기 도구로 결과를 검증한다.

- 폴더 격리 세션: Source Control에서 변경을 stage하고 commit한다.
- Worktree 격리 세션: 작업을 현재 작업 공간에 apply·merge하거나 세션 브랜치를 checkout한다.
- Cloud 세션: pull request를 검토하거나 브랜치를 로컬에서 checkout한다.

Agents window의 Changes view에서는 Branch Changes 드롭다운으로 브랜치 변경, 미커밋 변경, 전체 변경, 마지막 에이전트 턴 변경을 선택할 수 있다. **Mark as Reviewed**로 파일 검토 상태를 기록할 수도 있다.

## Worktree 변경 통합 전 확인

1. 세션의 기준 브랜치와 대상 작업 공간 브랜치를 확인한다.
2. 대상 작업 공간의 무관한 변경을 커밋하거나 stash한다.
3. 추적·미추적 파일을 포함해 모든 변경을 검토한다.
4. 관련 테스트를 실행하고 통합 시 충돌을 해결한다.
5. 통합된 결과를 다시 테스트한 뒤 세션을 보관하거나 삭제한다.

변경이 아직 반영되지 않은 상태에서 세션을 삭제하면 worktree에만 있던 파일을 잃을 수 있다.

## Checkpoint와 요청 편집

- **요청 편집**: 이전 프롬프트를 수정하면 그 요청과 이후 요청에서 만든 변경을 되돌린 뒤 수정된 프롬프트를 다시 보낸다.
- **Checkpoint 복원**: 대화 기록은 유지하면서 특정 시점까지 모든 파일 변경을 되돌린다.
- **Redo**: 복원으로 취소한 변경을 다시 적용한다.
- **Fork**: 특정 checkpoint까지의 대화를 기반으로 독립 세션을 만든다.

Checkpoint는 임시 작업 기록이며 영구 버전 관리나 Git을 대체하지 않는다.

## 민감한 파일

변경 후 diff 검토와 민감한 파일의 사전 승인은 별개다. `chat.tools.edits.autoApprove`에 glob 규칙을 지정해 `.env`나 `.vscode/*.json` 같은 파일은 편집 전에 항상 승인을 요구할 수 있다.

확장 호스트 세션에서는 편집이 pending 상태로 표시되며 Keep, Undo로 개별 편집이나 전체 편집을 확정한다. 자동 수락을 사용하더라도 커밋 전 diff를 검토해야 한다.

## 핵심 요약

AI 변경은 즉시 적용되는 일반 작업 트리 변경으로 생각하고 diff·테스트·Git 검토 흐름을 거쳐 통합해야 한다. Worktree와 checkpoint는 실험과 격리를 돕지만, 최종 보존과 복구에는 commit과 branch 관리가 필요하다.
