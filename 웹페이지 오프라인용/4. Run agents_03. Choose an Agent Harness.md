# Choose and Use an Agent Harness 요약

- 원문 수정일: 2026-10-07

## 하니스의 역할

하니스는 에이전트 세션의 도구 호출, 컨텍스트, 실행 위치와 코드 변경을 조정한다. 모델을 바꾸는 것은 하니스를 바꾸는 것과 다르다. 하니스마다 사용 가능한 도구·모델·권한·사용자 지정 방식이 다를 수 있다.

| 대상 | 실행 환경 | 주된 사용 사례 |
| --- | --- | --- |
| Copilot | 로컬, 원격 Agent Host 또는 Dev Container | 일상적인 코딩과 세션을 이어가는 작업 |
| Claude / Codex | 로컬 컴퓨터 | 각 제공자의 에이전트 기능과 작업 흐름 사용 |
| Cloud | 제공자의 원격 인프라 | GitHub 저장소에서 독립 작업 후 PR로 전달 |
| Local | 현재 VS Code 확장 호스트 | 현재 작업 공간과 VS Code 확장 도구 중심 작업 |

## 세션 설정과 시작

Chat view나 Agents window의 Session Target에서 사용 가능한 하니스를 선택한다. Agent는 지침·도구·행동 방식을, Language model은 추론과 응답 특성 및 크레딧 사용을, Permissions는 확인이 필요한 작업을 정한다. Agents window에서는 코드 격리도 선택할 수 있다.

기본 작업은 Copilot, 구현은 Agent, 사전 접근 검토는 Plan, 권한은 Manual로 시작하는 방식을 권장한다. 진행 중인 Local 세션은 Session Target을 바꾸어 대화 이력과 컨텍스트를 다른 하니스나 Cloud로 넘길 수 있다.

## 코드 격리

- **Folder**는 현재 작업 공간과 미커밋 파일을 사용한다.
- **New Worktree**는 커밋된 기준 브랜치로부터 별도 Git worktree를 만들어 작업을 격리한다.

Worktree는 최소 한 번 커밋된 Git 저장소가 필요하며, 기본적으로 미커밋 변경과 무시 파일은 포함하지 않는다. 코드 변경 위치를 분리할 뿐 명령이나 네트워크를 제한하는 보안 경계는 아니므로 샌드박스와 권한 설정은 별도로 고려한다. Local 세션은 현재 작업 공간을 사용한다.

## 선택 기준

일반적인 코딩은 Copilot, 특정 공급자의 익숙한 도구와 설정이 필요하면 Claude나 Codex, 로컬 편집기 컨텍스트 없이 GitHub 기반 작업을 맡기려면 Cloud, VS Code 확장 호스트의 기능이 필요한 경우 Local을 고려한다. 전환 시 도구·모델·권한이 바뀔 수 있으므로 새 설정을 확인한다.

## 핵심 요약

하니스는 세션 실행 환경과 작업 방식을 결정한다. 작업의 컨텍스트 필요성, 도구·공급자 기능, 변경 격리 요구를 기준으로 대상을 고르고, 권한과 샌드박싱은 별도 보안 제어로 설정한다.
