## 에이전트 하니스란

에이전트 하니스는 에이전트 루프를 실행하는 런타임이다. 세션을 관리하고, 도구를 호출하며, 코드 변경을 적용한다. VS Code의 **Session Target**은 사용할 하니스와 실행 환경을 선택하는 제어 요소다.

## 세션 선택 요소 구분

채팅 입력 영역의 선택 항목은 서로 다른 역할을 가진다.

- **에이전트 하니스**: 에이전트 루프와 공급자별 도구·기능을 조정한다. 예: Local, Copilot, Claude, Codex
- **실행 환경**: 도구 호출과 코드 변경이 실행되는 위치를 결정한다. 로컬, 원격 컴퓨터, 클라우드가 있다.
- **에이전트 역할**: Agent, Plan, Ask 또는 사용자 정의 에이전트처럼 작업별 지침과 도구를 제공한다.
- **언어 모델**: 추론하고 응답을 생성한다. 하니스와 다른 위치에서 실행될 수도 있다.

하니스는 프롬프트와 컨텍스트를 모델에 전달하고, 모델이 요청한 도구를 실행한 뒤 결과를 다시 모델에 전달한다.

## 지원되는 하니스

- **Local**: VS Code 확장 호스트에서 실행되며 VS Code 도구, 확장 도구, MCP 서버, VS Code에 설정된 모델을 사용할 수 있다.
- **Copilot**: Copilot SDK를 사용하고 Agent Host에서 실행된다.
- **Claude**: 로컬 세션에서는 Anthropic Claude Agent SDK를 사용하며 클라우드 에이전트로도 제공된다.
- **Codex**: OpenAI Codex를 사용하며 로컬과 클라우드 세션을 지원한다.

공급자 SDK는 고유 기능을 제공하고, VS Code는 세션 관리, 작업 공간 선택, 채팅, 변경 검토, 핸드오프 같은 공통 경험을 제공한다.

## 실행 위치와 코드 격리

에이전트는 다음 위치에서 실행할 수 있다.

- **내 컴퓨터**: 로컬 폴더 또는 Git worktree에서 작업하고 터미널·테스트 결과에 접근한다.
- **클라우드**: GitHub 저장소를 대상으로 원격 실행하고 pull request를 만든다.
- **원격 컴퓨터**: SSH 또는 개발 터널로 연결된 호스트에서 소스 코드 가까이 실행한다.

로컬 실행에서는 다음 격리 방식을 선택한다.

- **폴더 격리**: 현재 작업 공간에서 직접 작업하며 미커밋 변경 사항을 보고 그 자리에서 수정한다.
- **Worktree 격리**: 커밋된 기준 브랜치에서 별도 Git worktree를 만들어 주 브랜치와 변경을 분리한다.

Worktree는 보안 경계가 아니다. 명령, 네트워크, worktree 밖 파일의 접근을 제한하려면 에이전트 샌드박싱을 사용해야 한다. Worktree 격리에는 최소 하나의 커밋이 있는 Git 저장소가 필요하다.

## Agent Host와의 관계

Agent Host는 하니스를 VS Code 창과 독립적으로 실행한다. 따라서 세션을 여러 클라이언트에서 공유하거나, 창을 닫은 뒤에도 실행을 계속하거나, 원격 호스트에서 작업할 수 있다.

## 핵심 요약

하니스, 실행 환경, 역할, 모델은 서로 다른 선택이다. 작업의 공급자별 기능, 실행 위치, 코드 격리 요구 사항과 감독 수준을 고려해 조합해야 한다.
