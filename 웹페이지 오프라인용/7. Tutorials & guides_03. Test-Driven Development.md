# Test-Driven Development 요약

- 원문: https://code.visualstudio.com/docs/agents/guides/test-driven-development-guide
- 문서 제목: Set up a test-driven development flow in VS Code
- 원문 수정일: 2026-08-19

## TDD 사이클

TDD는 다음 세 단계를 반복한다.

1. **Red**: 올바른 이유로 실패하는 테스트를 작성한다.
2. **Green**: 테스트를 통과하는 최소 구현을 작성한다.
3. **Refactor**: 동작을 유지하며 구조·이름·중복을 개선한다.

각 단계가 끝날 때 테스트를 실행하고 경계값과 오류 조건을 확인한다.

## VS Code에서 구성

`testing.instructions.md`에 테스트 프레임워크, 파일 구조, 명명 규칙, 실행 명령을 기록하고 `applyTo` 범위를 지정한다. Red, Green, Refactor 역할을 각각 Custom agent로 만들 수 있다.

- Red agent: 구현하지 않고 실패 테스트만 작성
- Green agent: 최소 구현과 테스트 실행
- Refactor agent: 동작 변경 없이 품질 개선과 재실행

Handoff로 Red → Green → Refactor → 다음 Red 흐름을 연결한다.

## 사람의 검토

각 단계 사이에서 사람이 테스트가 요구 사항을 올바르게 표현하는지, 실패 원인이 예상한 것인지, 구현이 불필요하게 넓지 않은지 확인한다. 한 agent가 전 과정을 수행하는 것보다 단계별 agent를 분리하면 검토 지점과 통제력이 늘어난다.

## 핵심 요약

VS Code의 TDD 흐름은 테스트 실패를 먼저 확인하고 최소 구현으로 통과시킨 뒤 리팩터링하는 작업을 agent 역할과 handoff로 구조화한다. 작게 진행하고 매 단계 즉시 테스트하며 사람이 결과를 검토해야 한다.
