# Trust & Safety 요약

- 원문: https://code.visualstudio.com/docs/agents/concepts/trust-and-safety
- 문서 제목: Trust and safety
- 원문 수정일: 2026-08-19

## 기본 원칙

AI가 생성한 결과는 반드시 검토해야 한다. VS Code는 에이전트가 파일을 변경하고 명령을 실행하며 외부 서비스에 접근할 때 사용자가 통제권을 유지하도록 여러 안전 장치를 제공한다.

- **적용 전 검토**: 파일 변경을 diff로 확인하고 Keep 또는 Undo를 선택한다. Checkpoint로 세션을 되돌릴 수 있다.
- **실행 전 승인**: 부작용이 있는 도구와 터미널 명령에 승인을 요구한다.
- **자율성 제한**: 수동 승인부터 자동 승인, Autopilot까지 권한 수준을 선택한다.
- **OS 수준 경계**: 에이전트 샌드박싱으로 파일 시스템과 네트워크 범위를 제한한다.
- **신뢰 경계**: 작업 공간, 확장, MCP 서버, 네트워크 도메인에 대해 명시적으로 신뢰를 부여한다.

커밋 전에는 엣지 케이스, 프로젝트 규칙, 보안 취약점 여부를 직접 확인해야 한다.

## 신뢰 경계

- **Workspace Trust**: 작업, 디버깅, 실행 가능한 workspace 설정을 허용할지 결정한다. 신뢰하지 않는 작업 공간은 Restricted Mode로 열리고 에이전트가 비활성화된다.
- **Extension Publisher Trust**: 확장 게시자를 신뢰해야 해당 확장을 설치하고 실행할 수 있다.
- **MCP Server Trust**: MCP 서버가 시작되어 도구를 제공하기 전에 서버별 신뢰를 요청한다. 설정 변경 후 다시 확인한다.
- **Network Domain Trust**: 에이전트가 URL에 접근하기 전에 도메인을 신뢰한다. `chat.agent.networkFilter`, `chat.agent.allowedNetworkDomains`, `chat.agent.deniedNetworkDomains`로 네트워크 범위를 관리할 수 있다.

신뢰는 명령 팔레트의 관련 명령으로 언제든 취소할 수 있다.

## Agent sandboxing

Agent sandboxing은 미리 보기 기능이며 OS 수준에서 에이전트가 접근할 수 있는 파일과 네트워크를 제한한다. 현재는 에이전트 세션의 터미널 명령(`runInTerminal`)에 적용된다. 샌드박스 안에서 실행되는 터미널 명령은 통제된 환경에 있으므로 자동 승인될 수 있다.

샌드박싱이 필요한 이유는 승인 피로, 자동 승인 규칙의 셸 구문 분석 한계, prompt injection, 외부 서비스에 대한 의도하지 않은 작업 때문이다.

### 파일 시스템 격리

기본적으로 작업 공간과 샌드박스 임시 폴더는 읽을 수 있고, 쓰기는 현재 작업 디렉터리와 하위 폴더로 제한된다. 홈 디렉터리의 읽기는 기본 거부되어 SSH 키, 셸 설정, 자격 증명 같은 민감한 파일을 보호한다.

명령에 필요한 경로는 명령별로 읽기 허용될 수 있으며, 추가 허용·차단 경로를 설정할 수 있다. 거부 규칙은 허용 규칙보다 우선하고, 자식 프로세스도 같은 제한을 상속한다.

### 네트워크 격리

샌드박싱과 무제한 네트워크 접근은 별도 설정이다. `chat.agent.sandbox.allowNetwork`가 꺼져 있으면 외부 연결은 기본 차단되고 허용한 도메인만 접근할 수 있다. 허용 도메인은 읽기뿐 아니라 해당 서비스에 변경 작업을 수행할 수 있으므로 필요한 경우에만 지정해야 한다.

### 플랫폼

- macOS: Apple Seatbelt 사용
- Linux 및 WSL2: bubblewrap과 socat 필요
- WSL1: 필요한 Linux 커널 기능이 없어 지원하지 않음

샌드박싱은 기본 제공 파일 도구에는 적용되지 않는다. 파일 읽기·편집·쓰기는 VS Code 권한 시스템을 사용하므로 변경 검토와 민감한 파일 보호를 함께 사용해야 한다. 전체 개발 환경을 격리하려면 dev container와 조합한다.

## 주의할 AI 한계

- 모델은 버그, 오래된 API, 누락된 경계 조건을 포함한 코드를 생성할 수 있다.
- 파일, 도구 출력, 웹페이지의 악성 내용이 에이전트의 행동을 바꾸는 prompt injection이 발생할 수 있다.
- 외부 서비스 접근 권한이 있으면 클라우드 리소스, 인프라, 저장소, 결제 관련 API에 의도하지 않은 작업을 할 수 있다.

따라서 AI 결과는 유용한 초안으로 취급하고, 테스트와 보안 검토를 거친 뒤 적용해야 한다.

## 핵심 요약

VS Code의 안전 모델은 변경 검토, 도구 승인, 권한 수준, 신뢰 경계, OS 수준 샌드박싱을 겹쳐 사용한다. 그러나 어떤 장치도 사람의 검토를 대신하지 않으므로, 특히 자동 승인·외부 네트워크·민감한 코드 작업에서는 결과와 접근 범위를 확인해야 한다.
