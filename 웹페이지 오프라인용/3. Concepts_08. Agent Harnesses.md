## 하니스란

하니스는 언어 모델을 실제 에이전트로 동작하게 만드는 런타임 계층이다. 모델에 컨텍스트와 도구를 연결하고, 세션 상태를 관리하며, 툴 호출과 권한을 조율한다.

즉, 모델이 "무엇을 해야 할지" 결정하면, 하니스가 "그 행동을 어떻게 실행할지"를 관리한다.

## 하니스와 다른 개념의 차이

- 모델 접근: 어떤 계정, 구독, API 키로 모델에 접근하는지
- 언어 모델: 추론 엔진 자체
- 에이전트 역할: Agent, Plan, Ask, Custom agent 등 작업 성격
- 세션 대상: 어떤 harness나 cloud target를 쓸지
- 실행 환경: 코드가 어디에서 실행될지

이 요소들은 서로 연관되지만 서로 다른 수준의 개념이다.

## 하니스가 바꾸는 것

하니스는 선택된 구현에 따라 다음을 결정한다.

- 지원하는 도구와 기능
- 모델 선택 범위
- 세션 동작
- 권한 모델 및 승인 규칙

다만 하니스 자체가 코드가 수정될 위치를 정하는 것은 아니다. 실행 환경이 이를 결정한다.

## 세션 타깃과 실행 환경

VS Code는 보통 다음 실행 형태를 지원한다.

- Copilot
- Claude
- Codex
- Cloud
- Local

실행 환경은 다음 중 하나가 될 수 있다.

- 로컬 기기
- 원격 호스트
- Dev Container
- 클라우드 인프라

## 코드 격리와 작업 트리

에이전트는 현재 워크스페이스에 직접 수정할 수도 있고, Git worktree를 이용해 별도 작업 디렉터리에서 작업할 수도 있다.

- 폴더 격리: 현재 워크스페이스에 직접 편집
- 작업 트리 격리: 별도 Git worktree에서 변경 적용

중요: worktree는 코드 분리 수단이지 보안 경계가 아니다. 샌드박싱이 별도로 필요하다.

## 핵심 요약

하니스는 에이전트 루프를 실제로 운영하는 런타임이며, 모델과 도구, 세션, 권한을 연결해 주는 중개 계층이다. 실행 환경과 함께 보면 VS Code 에이전트는 어디서, 어떤 코드에, 어떤 방식으로 작업을 수행할지 전체 구조를 이해할 수 있다.
