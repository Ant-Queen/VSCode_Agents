# Customization 요약

- 원문: https://code.visualstudio.com/docs/agents/concepts/customization
- 문서 제목: Agent customization
- 원문 수정일: 2026-08-19

## 에이전트 맞춤화란

AI 모델은 일반적인 지식은 갖고 있지만 코드베이스, 팀의 개발 방식, 내부 시스템은 알지 못한다. 에이전트 맞춤화는 지속적인 컨텍스트, 반복 워크플로, 전문 역할, 외부 도구, 결정적 제어를 추가해 에이전트를 프로젝트 환경에 맞춘다.

## 맞춤화가 바꾸는 것

- **컨텍스트 제공**: 지침으로 코딩 표준, 아키텍처와 규칙을 전달한다.
- **반복 작업 정의**: Agent skills와 prompt files로 작업별 절차를 패키지한다.
- **역할 구성**: Custom agent에 지침, 도구, 모델을 조합해 전문 역할을 만든다.
- **기능 추가**: MCP 서버로 데이터베이스, 브라우저, API 같은 외부 시스템과 연결한다.
- **동작 강제**: Hooks로 모델의 선택과 관계없이 특정 시점에 명령을 실행한다.
- **패키지 설치**: Agent plugins로 관련 맞춤화 여러 개를 하나의 패키지로 배포한다.

지침은 모델의 결정을 유도하고, 도구는 행동의 범위를 넓히며, hooks는 모델의 판단 바깥에서 실행된다. 따라서 지침으로 규칙을 설명하는 것과 hook으로 규칙을 강제하는 것은 다르다.

## 맞춤화 선택 기준

다음 질문으로 맞춤화 유형을 선택한다.

- 자동 적용할 것인가, 요청할 때만 사용할 것인가?
- 지침, 워크플로, 기능 추가, 강제 동작 중 무엇인가?
- 모델이 사용 시점을 결정해야 하는가?

| 목적 | 적합한 맞춤화 | 활성화 방식 |
| --- | --- | --- |
| 프로젝트 전체 표준 적용 | Always-on instructions | 모든 요청에 자동 포함 |
| 특정 파일·작업에 지침 적용 | File-based instructions | 패턴이나 작업이 일치할 때 포함 |
| 지원 리소스가 있는 워크플로 교육 | Agent skills | 작업과 일치하거나 직접 호출 |
| 저장된 작업을 필요할 때 실행 | Prompt files | slash command로 호출 |
| 전문 역할과 도구 구성 | Custom agents | 사용자가 선택하거나 서브에이전트로 호출 |
| 외부 시스템 연결 | MCP | 필요한 MCP 도구를 에이전트가 호출 |
| 생명주기 시점에 코드 실행 | Hooks | 설정된 이벤트마다 VS Code가 실행 |
| 여러 맞춤화를 묶어 설치 | Agent plugins | 패키지별 규칙에 따라 활성화 |

반복되는 프로젝트 컨텍스트를 줄이는 것이 목적이면 instructions부터 시작한다. 반복 작업, 전문 역할, 외부 연결 또는 항상 실행해야 하는 동작이 확인될 때 다른 유형을 추가한다.

## 모델 주도와 결정적 동작

대부분의 맞춤화는 모델에 지침이나 선택지를 제공한다. 모델은 요청과 컨텍스트를 보고 skill의 관련성을 판단하거나 도구 호출 시점을 선택하므로 결과가 달라질 수 있다.

Hooks는 결정적이다. 설정된 이벤트가 발생하면 모델이 기억했는지와 관계없이 실행된다. 반드시 수행해야 하는 포맷터, 위험 명령 검증 등에는 hook이 적합하고, 사고 방식이나 코드 작성 방식을 안내하는 데는 instructions가 적합하다.

## 맞춤화 조합

예를 들어 pull request 준비 에이전트는 instructions로 저장소 표준을, Custom agent로 역할과 도구 제한을, skill로 절차와 템플릿을, MCP로 이슈 트래커 연결을, hooks로 필수 검증과 금지 명령 차단을 구성할 수 있다.

각 계층의 책임을 분리하면 표준을 바꾸면서 워크플로는 유지하거나 외부 시스템을 교체하면서 역할은 유지할 수 있다. Plugin은 이런 구성을 조직 전체에 배포하는 방법이다.

## 적용 범위

- **사용자**: 모든 작업 공간에서 개인적으로 사용한다.
- **작업 공간 또는 저장소**: 프로젝트와 함께 저장하고 기여자와 공유한다.
- **조직**: 여러 저장소에 중앙 정책으로 적용한다.

개인 취향은 사용자 범위에, 프로젝트 아키텍처와 팀 워크플로는 저장소 범위에, 조직 전체 요구 사항은 조직 범위에 두는 것이 좋다. 맞춤화 유형과 하니스에 따라 지원 범위는 다를 수 있다.

## 핵심 요약

맞춤화는 에이전트에게 프로젝트 지식을 반복해서 설명하는 비용을 줄이고, 필요한 역할과 외부 기능을 제공하며, 반드시 지켜야 할 동작을 강제한다. 목적과 활성화 방식에 맞춰 가장 좁은 범위의 맞춤화를 선택해야 한다.
