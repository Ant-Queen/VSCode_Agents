## Context engineering이란

Context engineering은 AI가 프로젝트에 맞는 판단을 하도록 제품·구조·기여 규칙 같은 정보를 선별해 제공하는 체계적인 방식이다. 핵심 정보가 여러 파일에 흩어져 있거나 코드만으로 추론하기 어려울 때 특히 유용하다.

## 프로젝트 컨텍스트 구성

다음 문서를 짧게 만들고 `.github/copilot-instructions.md`에서 링크한다.

- `PRODUCT.md`: 제품 기능과 목표
- `ARCHITECTURE.md`: 전체 구조와 설계 원칙
- `CONTRIBUTING.md`: 개발·기여 규칙

초기에는 가장 중요한 정보만 넣는다. 반복되는 AI 오류를 해결할 때만 규칙을 추가하고, 과도한 문서와 중복을 피한다.

## 계획과 구현 흐름

1. **Curate**: 프로젝트 전체 컨텍스트를 지침으로 정리한다.
2. **Plan**: Plan agent나 읽기 전용 planning agent로 요구 사항·설계·작업·질문을 만든다.
3. **Implement**: 승인된 계획과 지침을 기반으로 구현한다.
4. **Review**: 테스트와 변경 검토로 결과를 확인한다.

계획 템플릿에는 요구 사항, 아키텍처와 설계, Markdown checklist 작업, 미해결 질문을 포함한다. 계획·구현·검토를 별도 세션으로 나누면 컨텍스트 혼합과 폐기 작업을 줄일 수 있다.

## 운영 원칙

Prompt caching을 활용하려면 안정적인 지침과 컨텍스트를 먼저 유지하고, 자주 바뀌는 파일과 터미널 출력은 뒤에 추가한다. Cache Explorer로 캐시 성능을 확인한다.

## 핵심 요약

좋은 컨텍스트는 많은 정보를 넣는 것이 아니라 의사결정에 필요한 정보를 구조화하는 것이다. 프로젝트 문서, 맞춤 지침, 계획·구현·검토 세션을 연결하되 작고 안정적인 컨텍스트에서 시작해야 한다.
