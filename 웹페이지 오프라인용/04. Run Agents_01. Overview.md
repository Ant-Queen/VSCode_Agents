# Run Agents 요약

- 원문: https://code.visualstudio.com/docs/agents/run/overview
- 문서 제목: Run agents in VS Code

## 인터페이스 선택

VS Code에서는 Chat view와 Agents window 모두 에이전트를 실행할 수 있다.

- **Chat view**: 현재 작업 공간의 코드, 에디터, 디버거, 터미널, 테스트와 대화를 함께 다루는 흐름에 적합하다.
- **Agents window**: 상위 수준 작업을 위임하고 여러 프로젝트·세션의 진행을 조정하는 데 적합하다.

어떤 세션을 서로 다른 인터페이스나 애플리케이션에서 이어갈 수 있는지는 선택한 하니스와 공급자에 따라 다르다.

## 작고 분명한 작업으로 시작

에이전트가 행동하기 전에 원하는 결과, 관련 맥락, 작업 경계, 성공을 보여 줄 검증 기준을 설명한다. 범위를 좁혀 요청하면 결과를 검토하기 쉽고 의도하지 않은 변경을 줄일 수 있다. 처음 사용하는 경우 Quickstart를 따라하고, 기존 저장소에서는 가이드의 하니스 요구사항과 권장 설정을 먼저 확인한다.

## 계획·실행·조정

요구사항이 불명확하거나 변경이 여러 영역에 걸치면 구현 전에 계획을 요청한다. 가정, 영향 파일, 검증 방법을 검토한 뒤 실행 여부를 결정한다. 작고 명확한 수정은 바로 구현하도록 요청해도 된다. 작업 중 접근이 빗나가면 실행 중인 요청에 보충 지시를 보내거나 중지할 수 있다.

## 검토·검증·복구

세션 목록으로 진행 상태를 확인하고, 작업이 끝나면 변경된 파일과 새 파일을 검토한다. 에이전트의 테스트 출력만 신뢰하지 말고 관련 테스트를 다시 실행하며 사용자 관점에서 동작을 확인한다. 요구사항에 맞고 검증을 통과한 변경만 통합한다.

요청을 중지해도 완료된 동작은 자동으로 취소되지 않는다. Checkpoint는 지원되는 작업 공간 파일과 대화 기록을 복원하지만 터미널 명령, 네트워크 요청, 배포 또는 외부 서비스 변경은 되돌리지 않는다.

## 필요한 경우에만 설정 조정

- **하니스와 실행 위치**: 다른 도구·사용자 지정·공급자 또는 실행 장소가 필요할 때 비교한다.
- **모델**: 작업 복잡도, 사용 가능 여부, 비용을 고려해 선택한다. 모델 변경은 하니스를 바꾸지 않는다.
- **코드 격리**: 폴더 또는 worktree로 편집 위치를 구분한다. worktree는 변경 사항을 분리할 뿐 시스템 접근을 제한하는 보안 경계가 아니다.
- **권한과 샌드박스**: 승인 정책과 파일 시스템·네트워크 제한은 서로 다른 보호 수단이므로 각각 설정한다.

## 핵심 요약

결과·맥락·경계·검증 기준이 명확한 작은 작업으로 시작하고, 실행 과정과 결과를 직접 검토한다. 기본 설정으로 작업을 익힌 다음, 필요한 이유가 생길 때만 하니스·모델·격리·권한을 조정한다.
