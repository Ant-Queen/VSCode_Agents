# OpenTelemetry Monitoring 요약

- 원문: https://code.visualstudio.com/docs/agents/guides/monitoring-agents
- 문서 제목: Monitor agent usage with OpenTelemetry
- 원문 수정일: 2026-08-19

## 관찰 대상

Copilot Chat은 OpenTelemetry(OTel)의 trace, metric, event를 내보내 에이전트·LLM·도구·hook·토큰 사용량을 관찰하게 한다. 권장 namespace는 `gen_ai.*`와 `github.copilot.*`이며 기존 `copilot_chat.*`도 호환성을 위해 제공된다.

Trace는 `invoke_agent`, `chat`, `execute_tool`, `execute_hook` 계층으로 구성되고 서브에이전트의 trace context도 전달된다.

## 수집 정보

모델·토큰·저장소·브랜치·도구·hook 결정·오류 유형 같은 메타데이터를 수집할 수 있다. 기본적으로 prompt, 응답, 도구 인자는 수집하지 않는다.

`github.copilot.chat.otel.captureContent`를 켜면 콘텐츠가 포함될 수 있으므로 민감한 코드와 자격 증명이 있는 환경에서는 신중히 사용한다.

## 설정과 전송

- `github.copilot.chat.otel.enabled`: OTel 사용
- `exporterType`: 전송 유형
- `otlpEndpoint`: OTLP endpoint
- `outfile`: 파일 출력
- DB exporter 설정: 데이터베이스 전송

`OTEL_*`와 `COPILOT_OTEL_*` 환경 변수가 설정을 덮어쓸 수 있으며 조직의 managed settings가 더 높은 우선순위를 가진다.

Copilot, Copilot CLI, Claude agent는 service name과 trace 연결 방식이 다를 수 있으므로 `service.name`과 `gen_ai.agent.name`으로 필터링한다. 인증 header와 content capture는 신뢰된 수집 환경에서만 사용한다.

## 핵심 요약

OpenTelemetry는 에이전트 실행 시간, 모델·토큰 비용, 도구와 오류를 표준 방식으로 관찰하게 한다. 운영 분석을 위해 메타데이터만 수집하는 기본값을 유지하고, 콘텐츠 수집은 개인정보·보안 영향을 검토한 뒤 제한적으로 활성화한다.
