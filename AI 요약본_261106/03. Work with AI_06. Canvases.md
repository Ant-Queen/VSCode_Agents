# Canvases 요약

- 원문: https://code.visualstudio.com/docs/agents/run/canvases
- 문서 제목: Use canvases with agents
- 원문 수정일: 2026-11-04

## Canvas의 개념과 활용

Canvas는 VS Code에서 에이전트와 함께 사용하는 대화형 시각 작업 공간이다. 채팅으로 모든 변경을 설명하는 대신, 보드·다이어그램·조절 가능한 입력 화면처럼 시각 요소를 직접 조작할 수 있다. 예를 들어 Kanban 보드에서 작업 카드를 옮기거나, 에이전트가 갱신하는 다이어그램을 살피거나, 화면 컨트롤을 조절해 그 값을 에이전트에 전달할 수 있다.

Canvas는 독립된 VS Code 문서가 아니라 Canvas 확장이 제공하는 화면이며, 이를 연 Copilot 세션과 연결된다. 화면은 편집기 탭으로 열리고, 해당 세션의 채팅과 함께 사용할 수 있다.

## 사전 조건과 지원 범위

- Canvas는 활성 에이전트 세션 안에서만 열 수 있으며, 단독으로 시작할 수 없다.
- VS Code 데스크톱에서 **Copilot harness**를 선택한 세션이 필요하다. 로컬 세션은 Chat view와 Agents window 모두에서 사용할 수 있다.
- `chat.canvases.enabled`를 켠 뒤 새 세션을 만들고 첫 메시지를 보내 세션을 초기화한다. 설정 변경은 새 세션부터 적용된다.
- Claude, Codex, Local harness 세션, 브라우저 클라이언트, 보조(auxiliary) 창에서는 지원되지 않는다.

원격 Agent Host의 Canvas는 Agents window에서 열 수 있다. 이 경우 `chat.canvases.enabled`와 `workbench.browser.enableRemoteProxy`를 켜고 원격 호스트에 연결한 뒤, 새 Copilot harness 세션을 시작해 메시지를 보낸다. 그 다음 에이전트에게 해당 원격 호스트의 확장이 제공하는 Canvas를 열어 달라고 요청한다.

## Canvas 확장 설치 또는 만들기

기존 Canvas를 사용하려면 활성 Copilot 세션에서 Command Palette의 **Chat: Open Customizations** 또는 Agents window 사이드바의 **Customizations**를 열고, **Browse**에서 **Canvases**로 결과를 필터링한다. Canvas 제공자로 표시된 플러그인을 선택하고 게시자와 내용을 확인한 다음 설치한다. 플러그인 설치 및 마켓플레이스 신뢰 확인은 일반 에이전트 플러그인 절차를 따른다. GitHub Copilot 앱을 통해 설치한 호환 Canvas 확장도 사용할 수 있다.

프로젝트에 필요한 화면을 직접 만들려면 세션에서 `/create-canvas` 스킬을 사용할 수 있어야 한다. 채팅에 `/create-canvas`와 원하는 UI 설명을 입력하면 스킬이 작업 공간 Canvas 확장을 만들고 화면을 연다. 예를 들어 다음처럼 요청할 수 있다.

```text
/create-canvas Create a Kanban board for this project with Backlog, In progress, and Done columns.
```

## Canvas 열기와 조작

에이전트에게 사용할 수 있는 Canvas를 나열하고 열도록 요청할 수 있다. 화면에 표시할 프로젝트나 데이터 등 Canvas가 요구하는 정보를 함께 제공한다. 입력이 필요 없는 Canvas는 다음 위치에서 직접 열거나 기존 화면으로 돌아갈 수 있다.

- Chat view 또는 Agents window의 입력창에서 **Add Context (+)** → **Canvas...**
- Chat view 제목 표시줄의 **New Chat (+)** → **Canvas**
- Agents window 편집기 영역의 **Add Tab (+)** → **Canvas**
- Agent Customizations 편집기의 **Canvases** 목록에서 **Ready to Open** 항목을 더블 클릭하거나, 선택한 후 `Enter` 또는 **More Actions** → **Open Canvas**

Canvas가 **Requires Input**으로 표시되면 목록에서 바로 열 수 없다. 에이전트에게 열어 달라고 요청하고 필요한 입력이나 구성을 함께 설명한다.

조작 방법과 지원 동작은 Canvas 확장마다 다르다. Canvas 자체 컨트롤로 내용을 확인·변경하고(예: 카드 생성이나 열 이동), 채팅에서 에이전트에게 수정을 설명할 수도 있다. 에이전트는 확장이 제공하는 동작을 사용해 Canvas 상태를 읽거나 갱신한다. 사용자의 직접 조작이 세션에 반영되는 방식도 확장 구현에 따라 달라진다.

## Canvas 확장 관리와 문제 해결

활성 로컬 Copilot 세션에서 Agent Customizations 편집기를 열고 **Canvases**를 선택하면 사용자·작업 공간·플러그인 등 출처별 확장과 Canvas를 확인할 수 있다. 확장을 펼쳐 제공 Canvas 목록을 확인하고, **More Actions**에서 원본 폴더를 열 수 있다. 플러그인에 포함된 확장은 **Show Plugin**으로 플러그인 정보를 살핀다.

사용자 또는 플러그인 확장에는 켜기/끄기 스위치가 있다. 스위치는 개별 Canvas가 아니라 확장 전체에 적용된다. 작업 공간 확장은 이 편집기에서 켜고 끌 수 없다. 확장을 끈 뒤에도 마지막으로 확인된 Canvas 항목이 목록에 남을 수 있지만, 꺼진 확장의 Canvas는 열 수 없다.

문제가 생기면 다음을 확인한다.

- Canvas 메뉴가 없으면 `chat.canvases.enabled`, 새 Copilot 세션 및 첫 메시지 전송 여부를 확인하고, 사용 가능한 확장이 있는지 살핀다. 원격 호스트는 `workbench.browser.enableRemoteProxy`도 확인한다.
- “Canvases are only available inside a session” 메시지가 나오면 활성 로컬 Copilot 세션을 선택한 후 Agent Customizations 편집기를 다시 연다.
- **Requires Input** 항목은 에이전트에게 필요한 정보를 전달해 열도록 한다.
- 확장은 보이지만 Canvas가 열리지 않으면 확장이 꺼져 있지 않은지 확인한다. 꺼진 확장의 마지막 Canvas 목록이 남아 있을 수 있다.

## 핵심 요약

Canvas는 Copilot 세션에 붙는 시각적 상호작용 표면으로, 채팅과 직접 조작을 결합한다. 지원 harness와 세션을 준비하고 신뢰할 수 있는 확장을 선택한 뒤, 확장이 요구하는 입력과 지원 동작을 확인하며 사용한다. 확장 기능에 따라 조작 내용이 에이전트 세션과 동기화되는 범위가 다를 수 있다.
