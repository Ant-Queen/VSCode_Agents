# Chat 요청에 컨텍스트 추가하기

- 공식 문서: https://code.visualstudio.com/docs/chat/copilot-chat-context
- 문서 제목: Add context to chat

## 1. 컨텍스트란?

컨텍스트(context)는 AI가 요청을 이해하고 답할 때 참고할 자료다. 파일을 열어 두었다고 해서 그 파일 전체가 항상 요청에 전달되는 것은 아니다. 활성 편집기나 선택 영역이 자동으로 참고되는 범위는 화면, harness, 설정에 따라 달라질 수 있으므로, 반드시 고려해야 하는 자료는 명시적으로 첨부한다.

관련 파일, 심볼, 오류 메시지 등을 알맞게 지정하면 답변이 구체적이고 검토하기 쉬워진다. 반대로 필요하지 않은 자료를 한꺼번에 많이 첨부하면 요청의 초점이 흐려질 수 있다.

## 2. `#` mention과 Add Context 사용하기

Chat 입력란에 `#`을 입력하면 사용할 수 있는 컨텍스트 항목을 찾을 수 있다. Chat view의 **Add Context** (`+`) 버튼에서도 항목을 선택할 수 있다. 제공 항목은 프로젝트와 VS Code 환경에 따라 다를 수 있으며, 대표적인 유형은 다음과 같다.

- **파일·폴더·심볼**: 수정하거나 설명받을 소스와 코드 요소를 지정한다. 심볼을 참조하려면 해당 심볼이 있는 파일을 편집기에서 먼저 연다.
- **`#codebase`**: 작업 공간에서 관련 코드를 검색하도록 요청한다. 코드베이스 전체 파일을 통째로 모델에 첨부하는 기능은 아니다. 알고 있는 관련 파일이나 심볼도 함께 지정하면 탐색 범위를 좁힐 수 있다.
- **터미널·진단·변경 사항**: 터미널 출력, 테스트 실패, 진단 오류, Source Control 변경 등 현재 작업의 근거를 첨부한다.
- **도구**: 작업에 필요한 도구를 요청에서 참조한다. 실제 제공 도구는 설정 및 연결된 확장에 따라 다르다.

파일이나 폴더는 Explorer, Search, 편집기 탭에서 Chat view로 드래그해 추가할 수도 있다. **Add Context**에서 **Files & Folders** 또는 **Symbols**를 고르는 방법도 있다.

### 프로젝트와 GitHub 자료

Agents window 세션에서는 첫 번째로 선택한 폴더 또는 저장소가 에이전트의 기본 실행 작업 공간이 된다. 추가 프로젝트는 요청 컨텍스트로 첨부할 수 있지만, 자동으로 별도의 작업 공간 루트가 되는 것은 아니다.

GitHub 저장소를 사용할 수 있는 환경이라면 **Add Context**에서 이슈나 Pull Request를 첨부하거나 해당 URL을 프롬프트에 붙여 넣을 수 있다. 여러 저장소를 쓸 수 있는 경우에는 먼저 올바른 저장소인지 확인한다.

## 3. 웹 페이지와 외부 URL

최신 API 문서처럼 웹 자료가 필요하면 URL을 프롬프트에 포함하거나 `#fetch`를 사용해 페이지 내용을 가져오도록 요청할 수 있다.

예시:

> 이 문서를 참고해서 현재 프로젝트의 설정을 업데이트해줘: https://example.com/api-guide

VS Code는 성능을 위해 페이지 내용을 잠시 캐시할 수 있다. 외부 URL에 접근하기 전에 확인을 요청할 수 있으므로, 익숙하지 않은 주소는 승인하기 전에 출처를 확인한다. 웹에서 가져온 내용은 참고 자료로 검토하고, 자동으로 신뢰할 수 있는 지침으로 취급하지 않는다.

## 4. 이미지와 통합 브라우저 컨텍스트

비전 기능을 지원하는 모델에는 스크린샷, UI 목업, 코드 이미지 등을 첨부하고 설명이나 구현을 요청할 수 있다. 이미지 내용 중 중요한 조건은 프롬프트에도 글로 적어 두면 의도를 전달하기 쉽다.

통합 브라우저에서는 페이지의 **Add to Chat** 메뉴를 통해 다음 자료를 첨부할 수 있다.

- **Add Element to Chat**: 선택한 HTML 요소와 관련 CSS, 스크린샷
- **Add Screenshot to Chat**: 현재 브라우저 화면 이미지
- **Add Console Logs to Chat**: 페이지의 콘솔 출력

브라우저의 로그인 페이지나 비공개 화면을 공유하기 전에는 화면에 개인정보나 비밀 값이 보이지 않는지 확인한다. 실제 페이지에서 에이전트가 상호작용하도록 하는 기능과 페이지 정보를 프롬프트에 첨부하는 기능은 목적이 다르다.

## 5. `@` participant에 대한 참고

이전 Chat에서는 `@vscode`, `@terminal` 같은 participant를 사용했지만, 공식 문서 기준으로 `@name` participant는 deprecated이며 Copilot harness에서 지원되지 않는다. Local harness 호환성이 필요한 경우가 아니라면 Copilot에 직접 요청하고 필요한 파일·도구·출력을 첨부한다. 도메인별 기능은 플러그인의 skill, MCP 도구 또는 확장 도구로 제공될 수 있다.

## 6. 컨텍스트를 잘 구성하는 예

막연한 요청:

> 로그인이 안 돼. 고쳐줘.

더 나은 요청:

> `#LoginForm`과 `#authService`를 확인해줘. 잘못된 비밀번호를 입력했을 때 화면에 오류가 표시되지 않아. 관련 테스트 실패 출력도 참고하고, 원인을 찾은 뒤 최소한으로 수정해줘. 수정한 동작을 검증하는 테스트도 실행해줘.

요청할 때는 다음을 함께 제공하면 좋다.

1. **목표**: 원하는 최종 동작
2. **대상**: 관련 파일·심볼·화면
3. **관찰한 문제**: 오류 메시지, 재현 단계, 테스트 출력
4. **제약**: 바꾸지 말아야 할 동작이나 사용해야 할 패턴
5. **완료 기준**: 테스트 통과, 화면 표시 등 확인 방법

## 핵심 요약

컨텍스트는 AI가 참고할 자료를 명시하는 방법이다. 반드시 필요한 파일·심볼·오류를 골라 첨부하고, `#codebase`는 전체 소스를 전달하는 기능이 아니라 관련 코드를 검색하도록 돕는 기능임을 기억한다. 웹 페이지와 비공개 브라우저 화면은 출처와 민감 정보를 확인한 뒤 공유한다.
