# Compare Model Results 요약

- 원문: https://code.visualstudio.com/docs/agents/run/compare-models
- 문서 제목: Compare model results (Preview)

## 기능 개요와 요구 사항

Agents window에서 동일한 코딩 작업을 여러 모델 또는 에이전트 하니스로 동시에 실행하고 결과를 나란히 비교할 수 있다. 적합한 시도를 선택하거나 여러 결과를 바탕으로 새 구현을 합성할 수 있다. 미리 보기 기능이며 편집기 Chat view에서는 사용할 수 없다.

사용하려면 Agents window 요구 사항을 충족하고, 브랜치·커밋·원격 저장소가 설정된 Git 저장소와 worktree 격리를 지원하는 Agent Host 하니스가 필요하다. 사용할 수 있는 모델과 하니스는 계정, 자격 증명, 조직 정책에 따라 다르다.

## 비교 설정

1. Agents window 설정에서 `sessions.chat.compareAgents.enabled`를 켠다. 기본값은 꺼져 있다.
2. **New**를 선택해 Git 저장소를 고른다.
3. 모델 선택기에서 **Compare Models**를 선택한다.
4. 2~10개의 시도를 추가한다. 비교에서는 Auto 라우팅을 사용할 수 없다. 지원되는 경우 같은 모델을 여러 번 추가해 서로 다른 thinking effort를 비교할 수 있다.
5. 자동 평가를 원하면 Judge 모델을 고른다. 여러 시도의 결과를 결합하려면 Synthesizer도 설정한다.
6. 설정을 완료하고 목표와 성공 조건을 동일하게 명시한 하나의 제한된 프롬프트를 입력한 뒤 **Run N Attempts**를 실행한다.

각 시도는 독립 세션으로 동시에 시작되며 기본적으로 타일형 화면에 표시된다. 각 시도는 저장소의 커밋된 상태를 기반으로 별도 Git worktree에서 실행되므로 원래 작업 트리의 미커밋 변경은 포함하지 않는다. Git 무시 파일이나 의존성이 빠져 있을 수도 있다.

## 결과 비교 및 합성

시도가 끝나면 각 결과의 변경 파일과 응답을 비교하고, 요구사항·제약·프로젝트 관례를 따르는지 확인한다. 적절한 후보의 테스트와 검사를 실행한다.

Judge를 설정한 경우 scorecard에서 추천, 시간·토큰 사용량, 판단 근거와 검증 증거를 확인할 수 있다. 평가 결과는 정답을 보장하지 않으므로 코드와 근거를 직접 검토하고 테스트해야 한다. 토큰 수치는 전체 사용량보다 낮게 표시될 수 있으며 크레딧이나 비용을 나타내지는 않는다.

Judge와 Synthesizer를 모두 설정했다면 결과를 검토한 뒤 **Synthesize**를 선택해 새 구현을 만들 수 있다. 합성은 별도의 격리 worktree와 그룹 세션에서 진행되며 기존 시도나 원래 작업 트리를 수정하지 않는다. 결과를 자동 병합하거나 PR을 만들지 않으므로 별도 검토와 검증이 필요하다.

## 권한 및 비용 주의

비교용 worktree 세션은 도구 승인 프롬프트를 건너뛰는 **Allow all** 권한으로 실행된다. worktree는 코드 변경만 분리하며 컴퓨터나 네트워크 접근을 제한하지 않는다. 실행 전에 승인 정책과 샌드박스 경계를 확인한다.

각 시도, Judge 평가, 합성은 별도의 모델 작업이므로 시도 수와 평가·합성 사용에 따라 추가 사용량이 발생한다. 결과를 고른 뒤에도 자동 통합되지 않으므로 변경사항과 새 파일을 검토하고 테스트한 다음 통합한다.

## 핵심 요약

같은 프롬프트와 커밋 상태에서 여러 모델의 결과를 비교하는 Preview 기능이다. worktree의 미커밋 상태 제외와 Allow all 권한을 이해하고, Judge 점수를 참고하되 결과를 직접 검토·테스트한 뒤 원하는 구현만 통합한다.
