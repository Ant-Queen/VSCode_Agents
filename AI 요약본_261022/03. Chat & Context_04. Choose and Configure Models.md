# VS Code 언어 모델 선택 및 구성

- 공식 문서: https://code.visualstudio.com/docs/agent-customization/language-models
- 문서 제목: AI language models in VS Code

## 1. 모델 선택은 왜 필요한가요?

모델마다 응답 속도, 복잡한 추론 능력, 이미지 입력, 도구 사용 등의 특성이 다르다. 같은 모델을 모든 작업에 사용하는 것보다, 작업의 난이도와 필요한 기능에 맞춰 선택하는 편이 효율적이다.

| 작업 유형 | 시작점으로 고려할 선택 |
| --- | --- |
| 짧은 질문, 작은 코드 수정 | 빠른 모델 |
| 복잡한 리팩터링, 설계 판단, 여러 단계 작업 | reasoning 모델 |
| 어떤 모델이 적절한지 직접 고르고 싶지 않음 | **Auto** |
| 조직에서 선택 가능한 모델이 제한됨 | 관리자 정책 및 현재 세션의 model picker 확인 |

이 표는 일반적인 기준이다. 실제 모델 목록과 성능은 사용 중인 harness, 계정, 조직 정책, VS Code 버전에 따라 달라질 수 있다.

## 2. Chat 모델 선택하기

Chat 입력란의 **language model picker**에서 현재 대화와 코드 편집에 사용할 모델을 고른다. 현재 응답 위에 포인터를 올리면 실제 응답에 사용된 모델을 확인할 수 있다.

모델 선택기에 **Auto**만 표시된다면 먼저 작업 공간이 신뢰된 상태인지 확인한다. Restricted Mode에서는 선택 가능한 모델이 제한될 수 있다. Copilot Business 또는 Enterprise 조직에서는 관리자가 특정 모델의 사용을 허용해야 할 수도 있다.

같은 작업을 여러 모델로 비교하고 싶다면 Agents window의 model comparison 기능이 제공되는지 확인한다. 기능의 제공 여부는 Preview 상태나 환경에 따라 다를 수 있다.

## 3. Auto 모델 선택과 최적화 우선순위

**Auto**는 작업의 복잡도와 모델의 실시간 사용 가능 상태를 평가해 각 요청에 맞는 모델을 선택한다. 사용할 때는 **Optimize for**에서 우선순위를 정할 수 있다.

- **Efficiency**: AI credit 사용량을 줄이는 쪽을 우선한다.
- **Balance**: 기능과 비용의 균형을 우선한다.
- **Intelligence**: 어려운 작업을 위한 더 높은 모델 역량을 우선한다.

Auto를 선택해도 모든 요청이 동일한 모델로 처리되는 것은 아니다. 응답에 실제로 어떤 모델이 사용됐는지 확인하려면 응답에 포인터를 올린다. 조직에서 기본 최적화 수준을 관리할 수 있지만, 현재 대화에서 사용자가 별도로 선택할 수 있는 범위는 정책에 따라 다르다.

## 4. Reasoning 모델의 Thinking Effort

일부 reasoning 모델은 요청에 투입할 추론량인 **Thinking Effort**를 조절할 수 있다. 모델 선택기에서 reasoning 모델을 고른 다음 모델 이름 옆의 화살표를 열어 수준을 선택한다. 일반적인 비-reasoning 모델에는 해당 메뉴가 나타나지 않는다.

기본 권장값과 adaptive reasoning 설정은 대부분의 작업에 적합하다. 더 높은 effort는 복잡한 문제를 풀 때 도움이 될 수 있지만, thinking token과 AI credit 사용량이 늘어날 수 있다. 단순 질문까지 항상 높은 수준으로 설정할 필요는 없다. 선택한 수준은 세션별로 기억된다.

## 5. Language Models editor에서 모델 관리하기

Chat의 model picker에서 톱니바퀴 아이콘의 **Manage Language Models**를 선택하거나 Command Palette에서 **Chat: Manage Language Models**를 실행한다. 편집기에서는 사용 가능한 모델과 주요 정보를 확인하고 선택기를 정리할 수 있다.

- 모델이 지원하는 기능(capability), 컨텍스트 크기, 과금·표시 상태를 확인한다.
- 검색 상자나 필터로 모델을 찾는다. 예: `@provider:"OpenAI"`, `@capability:tools`, `@capability:vision`, `@capability:agent`, `@visible:true`
- 눈 아이콘으로 model picker에 표시할지 숨길지 정한다.
- 자주 쓰는 모델은 pin하여 선택기 상단의 Pinned 영역에 고정한다.

모델이 목록에 보이는 것만으로 특정 기능을 지원한다고 가정하지 않는다. 에이전트 작업에는 tool calling, 이미지 작업에는 vision 지원처럼 현재 작업에 필요한 capability를 확인한다.

## 6. BYOK: 내 모델 공급자 연결하기

**Bring Your Own Key (BYOK)**는 호환되는 공급자의 모델을 VS Code Chat과 연결하는 방식이다. VS Code에 기본 제공되지 않는 모델, 직접 호스팅한 모델, Ollama 같은 로컬 모델을 사용할 수 있다. 설정한 BYOK 모델은 GitHub 계정이나 Copilot 플랜 없이도 사용할 수 있지만, 모든 VS Code AI 기능을 대체하지는 않는다.

모델을 추가하는 방식에는 기본 제공 공급자, Marketplace의 model provider 확장, Custom Endpoint 등이 있다. Custom Endpoint를 구성할 때는 해당 공급자와 모델이 지원하는 API 형식 및 기능을 확인한다. 에이전트에서 사용할 모델은 도구 호출을 지원해야 제대로 동작한다.

BYOK는 현재 문서 기준 Chat과 일부 utility task에 적용된다. semantic search, inline suggestions(코드 자동 완성), embedding 기반 기능 등은 여전히 GitHub 계정이나 Copilot 플랜이 필요할 수 있다. Copilot harness 세션에서 BYOK 모델을 사용하려면 `chat.agentHost.byokModels.enabled` 설정이 필요할 수 있으며, 해당 기능은 실험적일 수 있다.

API 키는 소스 코드나 공유 설정 파일에 직접 입력하지 않는다. VS Code가 제공하는 입력 변수 또는 보안 저장 방식을 사용하고, 로그·스크린샷·프롬프트에 키가 노출되지 않도록 확인한다.

## 7. 로컬 모델과 On-device 모델은 다릅니다

BYOK 로컬 모델은 사용자가 공급자나 실행 환경을 직접 구성하는 모델이다. 반면 **On-device model**은 Copilot이 제공·관리하는 로컬 모델 기능으로, GitHub 로그인 및 Copilot harness 등 별도 조건이 적용된다. 따라서 “내 PC에서 실행된다”는 사실만으로 BYOK와 On-device 모델을 같은 기능으로 간주하면 안 된다.

로컬 모델의 기능과 안전 필터는 클라우드 모델과 다를 수 있다. 특히 에이전트의 작업을 자동 승인하도록 설정한 환경에서는 모델의 제안과 실행 결과를 더 주의 깊게 검토한다. 지원 모델, 하드웨어 요구 사항, 실험적 기능 여부는 공식 문서에서 현재 상태를 확인한다.

## 8. Chat 외 기능의 모델 설정

Chat 모델과 Inline Chat 모델, 코드 자동 완성 모델은 서로 다른 설정 경로를 가질 수 있다. 편집기 Inline Chat의 기본 모델은 `inlineChat.defaultModel`로 지정한다. Inline suggestions 모델은 Chat 메뉴의 **Configure Inline Suggestions**에서 별도로 관리한다.

## 핵심 요약

먼저 빠른 모델·reasoning 모델·Auto 중 작업에 맞는 선택을 하고, 필요할 때만 Thinking Effort를 높인다. Language Models editor에서 기능과 표시 상태를 확인하고, BYOK나 로컬 모델을 추가할 때는 기능 범위·도구 호출 지원·자격 조건·API 키 보안을 함께 점검한다.
